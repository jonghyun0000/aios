# 1단계 — 자동 응답과 지연 측정

2026-09-12. 로컬 전용 개선이며 외부 배포·새 모델 구매·사용자 설정 파일 교체는 하지 않았다.

## 구현

- 웹 기본값은 `mode:auto`. 빠른 응답·깊이 생각을 직접 선택할 수 있다. 기존 API의 mode 없는 호출은 기존 reasoning/context 옵션을 유지한다.
- 별도의 분류 모델을 호출하지 않는다. 명확한 수식은 계산, 복잡한 코드·논리·번역·긴 질문·도구 사용은 추론, 짧은 일반 질문은 빠른 경로를 사용한다. 타입이 명시된 짧은 단일 함수 작성은 빠른 경로이며 수정·파일 실행·보안·재귀 등은 제외한다. 규칙이 모호한 의도를 완벽히 판별하지는 못한다.
- 계산 경로는 BigInt 분수 파서로 +, -, *, /, 괄호, 유한소수, 음수를 처리한다. eval/Function/셸을 사용하지 않는다. 0.1+0.2는 0.3, 순환소수는 정확한 분수로 표시한다. 0 나눗셈은 오류 설명을 반환한다.
- 수식 길이·토큰·숫자 자릿수를 제한하고, URL·코드·날짜·전화번호·혼합 지시를 그대로 계산하지 않는다. 단위·백분율·거듭제곱·서술형 수학은 이 계산기의 보장 범위 밖이다.
- 계산도 사용자/AI 메시지를 DB와 현재 대화에 저장하지만 모델·임베딩을 호출하지 않는다.
- 도구 없는 대화는 별도의 짧은 일반 응답 지시를 사용한다. 도구를 켜면 기존 코딩 에이전트 지시와 실행 경로를 보존한다.
- 사용자 시작기는 Ollama 네이티브 API와 실제 8192 컨텍스트를 명시한다. 기존에는 카탈로그 32768과 실제 모델 4096이 달랐다. `.env.local`은 수정하지 않았다.
- 입력·출력 예산을 분리하고 오래된 문맥이 제외되면 안내한다. 단일 입력이 한도를 넘으면 나누어 보내라고 알린다. 원본 대화는 삭제하지 않는다.

## 시간 표시의 의미

‘이번 응답 시간’은 이번 화면의 마지막 응답에만 표시한다. 새로고침/대화 이동 시 사라지며 과거 기록의 성능 통계 저장 기능은 아니다.

| 구간 | 측정 범위 |
|---|---|
| 입력/답변 저장 | DB + 현재 대화 기록, 답변 저장에는 후처리 이벤트 전달 포함 |
| 기억·자료 검색 | 메모리와 RAG의 병렬 수집 벽시계 시간 |
| 앱 대기열 | 이 API 프로세스의 로컬 모델 동시성 게이트 대기 |
| 모델 적재 / 입력 처리 / 추론·답변 생성 | Ollama가 제공하는 실제 duration 필드, ns→ms 변환 |
| 첫 글자까지 | 응답 엔진 시작부터 첫 가시 텍스트까지. 내부 사고 토큰과 다름 |
| 앱 전체 | 응답 엔진 시작부터 답변 저장과 후처리 전달까지. 앞선 권한/세션 조회·브라우저 연결/재조회 시간 제외 |

Ollama 전체와 앱 전체, 첫 글자까지는 다른 구간을 포함하므로 서로 더하지 않는다. 모델 서버 내부 큐 대기를 앱 대기열과 동일하다고 주장하지 않는다. 호환 API가 제공하지 않는 모델 세부 시간은 0으로 지어내지 않고 생략한다. 원천 필드는 [Ollama Chat API](https://docs.ollama.com/api/chat)를 따른다.

## 반복 평가 설계

`apps/verify/src/eval/stage1.ts`: 50문제 × 3회 × 빠른/자동 = 300회. 같은 문제와 채점 기준을 쓰고 쌍마다 실행 순서를 바꾼다. 형식·한국어·산술·논리·실행 가능한 코드·대화 맥락을 포함한다.

실제 정책→오케스트레이터→라우터→qwen3:8b를 사용한다. DB/장기기억은 고정된 메모리 픽스처로 격리하므로 이 수치를 웹 전체의 왕복 지연으로 해석하지 않는다. 두 모드 모두 현재의 동일한 모델·8192 컨텍스트·일반 대화 지시를 사용한다. 이전 빌드와의 전체 성능 비교가 아니라 **현재 설정에서 응답 정책의 비교**다.

`stage1-latency.ts`는 별도로 실제 사용자 API의 모델 비상주/상주·계산·연속 대화를 각각 3회 측정한다. 비상주 조건은 모델 해제 후 `/api/ps`로 확인한다. 다른 모델 평가와 동시에 실행하지 않는다.

결과는 `/Volumes/T7/bigdata/eval-baselines/stage1/`에 전체 응답·시간·실패를 포함해 저장한다. 개발 중 중단한 보고서는 `complete:false`이며 최종 통계에서 제외한다. 성공 표본만 남기도록 지우지 않는다.

## 검증 결과

### 50문제 × 각 3회: 완료

최종 보고서 `paired-2026-09-11T16-07-03.465Z.json` (위 stage1 폴더).
스위트 SHA-256: `a3516c8b1e7c5f4dfff98c5ad6cdc26188db7a9b4442aa3afeedd31e28567ee0`.

| 범주 | 빠른 모드 통과 | 자동 모드 통과 |
|---|---:|---:|
| 출력 형식 | 24/24 | 24/24 |
| 한국어 | 17/18 | 18/18 |
| 코드 실행 검사 | 21/21 | 21/21 |
| 정밀도·모름 인정 | 3/6 | 6/6 |
| 추가 사칙연산 | 24/36 | 36/36 |
| 논리·서술형 계산 | 24/30 | 30/30 |
| 대화 맥락 | 14/15 | 13/15 |
| 전체 | **127/150** | **148/150** |

이는 정의된 검사 통과율이다. 일부 실패는 내용 오답이 아니라 요청한 출력 형식 위반이다.
Wilson 95% 구간: 빠른 78.0–89.6%, 자동 95.3–99.6%. 같은 50문제를 반복한 표본이며 독립된 사용자 요청 150건을 대표하지 않는다. 일반 정답률 보장으로 사용하지 않는다.

자동 실패 2건은 `context.preference`에서 한국어 설정을 영어로 답한 경우다. 빠른 모드도 같은 문제에서 1회 틀렸다. **맥락 범주는 관측상 1건 하락했으므로 모든 범주에 무회귀라고 주장하지 않는다.** 해당 자동/빠른 경로가 동일한 모델 요청·대화 맥락을 전달함을 단위 검사로 확인했다. 반복 실패는 실제 모델의 불안정성으로 남긴다.

자동 선택 분포: 정확 계산 39, 빠른 응답 75, 깊이 생각 36. `17*23+41`은 빠른 모드 0/3(393), 자동 계산 3/3(432). 자동의 코드 21/21은 실제 함수를 실행해 채점했다.

전체 완료 중앙값은 빠른 0.533초, 자동 0.679초이며 p95는 2.797초 vs 18.687초다. **자동이 모든 요청을 더 빨리 처리한다는 주장은 하지 않는다.** 논리 과제에서 자동의 완료 중앙값 16.325초와 30/30을 얻는 대신, 빠른 모드는 0.400초와 24/30이었다. 작은 함수는 자동에서도 빠른 경로를 써 코드 완료 중앙값 1.974초였다.

정확 계산의 엔진 내부 중앙값 0.131ms는 저장/검색을 격리한 수치이므로 웹 응답 시간으로 인용하지 않는다. 실제 API 시간은 별도 측정한다. 개발 중 일부 정적 검사 및 공유 Mac의 다른 프로세스 부하가 존재했으므로 이 엔진 지연을 전용 기기의 절대 성능으로 일반화하지 않는다.

### 실제 API·브라우저·프로토콜

실제 사용자 API의 최종 시간 보고서: `api-latency-2026-09-11T16-24-19.448Z.json`.
아래는 각 3회 중앙값이며 단일 요청 HTTP 왕복과 응답 저장까지 포함한다.

| 조건 | 첫 글자 | 완료 | 유효 응답 |
|---|---:|---:|---:|
| 모델을 내린 뒤 인사 요청 | 8.374초 | 9.060초 | 3/3 |
| 모델 상주 상태, 같은 인사 요청 | 0.083초 | 0.712초 | 3/3 |
| 정확 계산 `17*23+41` | 0.007초 | 0.010초 | 3/3 |
| 9턴 대화 후 처음 프로젝트명 회상 | 0.382초 | 0.686초 | 3/3 |

재적재 조건의 완료 범위는 2.466–9.661초, 모델 적재 자체의 중앙값은 7.613초였다. 앞선 실행에서는 완료 11.657초도 관측됐다. OS 파일 캐시는 비우지 않았고 Mac 재부팅부터의 전체 시작 시간은 측정하지 않았다. 따라서 **첫 실행도 항상 3초 이내** 같은 주장은 하지 않는다. 상주 상태의 입력 처리 중앙값 58ms, 생성 625ms와 재적재 조건의 입력 처리 744ms를 구분한다.

이전 시간 보고서 `api-latency-2026-09-11T16-22-04.250Z.json`은 인사 검사 정규식이 ‘처음 뵙겠습니다/처음 만난 동료님’을 오탐했다. 정상 표현과 무관한 표현을 구분하는 검사기를 단위 검증한 후 전체 12조건을 다시 실행했다. 원본은 수정하거나 삭제하지 않았다. 이 변경은 50문제 품질 채점과 무관하다.

실제 Ollama 도구 호출→결과 전달→응답, 스트림 중단, 중단 후 다음 요청 복구를 각각 **3/3** 확인했다. 도구는 메모리 안의 테스트 조회이며 파일을 변경하지 않았다. 보고서 `protocol-2026-09-11T16-21-07.651Z.json`.

단위 검사에는 계산 1,323개 정수 조합, 소수/분수/큰 정수, 날짜/코드 오인 방지, UTF-8/줄 경계 스트림, 정상 종료 유실·잘린 도구 호출, 취소/게이트 반환, 저장/문맥/추론 옵션 유실 검출을 포함한다.

최종 `typecheck lint unit build`: **4 PASS / 0 FAIL**. 최종 브라우저: **69 PASS / 0 FAIL / 3 SKIP** (총 72개, 1.3분). 3 SKIP은 데스크톱에서 제외한 모바일 전용 검사이며 모바일에서는 통과했다. Enter/IME·사이드바·계산 결과 저장/새로고침·계측 상세·모바일 배치·오류 주입·접근성·색 대비를 확인했다.

최종 서버는 `http://127.0.0.1:8791`, `/readyz`에서 DB/Redis 정상. 고아 esbuild 프로세스가 없는 것을 확인했다. 과거의 21단계 전체 검증을 이번에 다시 수행한 것은 아니다. 외부 계정·대규모 프로젝트·무인 파일 수정의 완전한 신뢰성은 이번 범위 밖이다.
