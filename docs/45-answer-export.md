# 45. 답변·대화를 근거와 함께 내보내기 (NEXT_STEPS 5-7)

작성 2026-09-30. §1~§2는 구현 전에 적었다. 사용자 우선순위 4(결과물을 저장·다시 열기·편집·내보내기)의 첫 단계다.

## 1. 현재 상태 (코드 확인)

- 공공통계 원자료는 CSV로 내려받을 수 있다(`Data.tsx`).
- 공공통계 → 채팅 분석 초안 → AI 답변까지는 이어진다(`docs/38`). 답변은 대화에 저장돼 다시 열 수 있다.
- **답변을 복사·저장·내보내는 수단이 없다.** 웹 소스에 답변용 클립보드·Blob·내려받기 코드가 없다. 결과를 보고서·메모로 옮기려면 화면에서 직접 선택해 복사해야 하고, 그러면 질문·근거 구간·시각이 빠진다.

## 2. 완료 기준 — 구현 전 등록

1. AI 답변마다 **"복사"**와 **"Markdown 저장"**이 있다. 결과에는 질문(바로 앞 사용자 메시지), 답변 원문, 작성 시각, 근거가 있으면 전달된 구간(파일·행 범위·전달 원문)과 "전달된 구간은 정확성 보증이 아님" 안내가 들어간다.
2. 대화 전체를 **Markdown 파일로 내보낼** 수 있다(제목·내보낸 시각·메시지 순서대로, 근거 포함).
3. 내용에 백틱이 있어도 코드 블록이 깨지지 않는다. 파일 이름은 대화 제목에서 안전한 문자만 쓴다.
4. 서버·DB 변경 없이 이미 받은 메시지로만 만든다. 외부 전송 없음.
5. 복사 실패(권한 거부 등)는 성공으로 표시하지 않고 알린다. 복사·저장 성공은 화면 낭독기에도 알린다.
6. 단위 시험(형식·코드 블록·파일 이름·근거 없는 옛 답변) + 실제 Chromium(내려받은 파일 내용 확인, 클립보드 내용 확인, 복사 실패 주입) + 결함 주입 + 정적 4단계·기존 채팅 회귀.

범위 밖(이번에 하지 않음): 앱 안에서 편집하는 결과 문서, 다시 불러와 이어 쓰기, PDF·Word 내보내기. 앱 안 편집은 새 저장소(DB·API)가 필요하므로 별도 항목으로 둔다.

## 3. 구현

- `apps/web/src/lib/answer-export.ts`: 답변 하나(바로 앞 질문 포함)·대화 전체를 Markdown 으로 만든다. 원문은 가공하지 않고 코드 블록에 넣으며, 내용 속 가장 긴 백틱보다 긴 울타리를 쓴다. 근거가 있으면 전달 구간·원문과 "정확성 보증 아님" 안내를 붙인다. 시각은 KST. 도구·시스템 메시지는 대화 내보내기에서 뺀다.
- `apps/web/src/pages/Chat.tsx`: 답변마다 "복사"·"Markdown 저장", 대화 머리에 "대화 내보내기"(답변이 없으면 비활성). 성공은 `role=status`, 실패는 `role=alert`. 서버·DB 변경 없음.

근거가 있는 답변은 모델 호출이 필요해, 브라우저 시험은 실제 서버에 대화를 만들고 **기록 응답만** 근거가 담긴 고정 메시지로 바꿨다. 근거 저장 자체는 `docs/39` 에서 실제 모델로 확인했다.

### 기존 접근성 메타 시험의 전제 조정
`a11y-workflows.spec.ts` 의 "결함 주입은 키보드 스크롤 퇴행을 실제로 검출한다"가 4건 실패했다. axe `scrollable-region-focusable` 은 **스크롤 영역 안에 초점 가능한 요소가 없을 때만** 위반이라, 답변 버튼이 생기자 `tabindex` 를 빼도 위반이 아니게 됐다. 제품의 대화 영역 `tabindex` 는 그대로 두고, 결함 주입 상태에서 답변 버튼도 함께 제거하도록 시험을 고쳤다(주석 포함). 긴 대화를 키보드로 읽는 기존 시험은 수정 없이 통과한다.

## 5. 남은 것
- 앱 안에서 결과를 편집·보관하는 "결과 문서", 다시 불러와 이어 쓰기, PDF·Word 내보내기는 하지 않았다(§2 범위 밖).
- 모델 이름은 메시지에 저장되지 않아 내보내기에 넣지 못했다.
- 실제 스크린리더 청취는 하지 않았다.
