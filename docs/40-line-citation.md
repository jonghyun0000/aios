# 40. 행 번호 인용 오류 줄이기 (NEXT_STEPS 5-2)

작성 2026-09-27. §1~§4는 **모델을 한 번도 돌리기 전에** 커밋한다. 결과는 §5 이후에 덧붙이고, 결과를 본 뒤 §1~§4를 고치지 않는다.

## 1. 문제

`docs/39` §2 재현: 40행의 사실을 `qwen3:8b`가 "39번째 줄"이라고 답했다. 구간 선택기는 블록 원문을 JSON 문자열 하나로 보내고 머리에 `lines 1-41` 범위만 적는다. 모델이 줄을 직접 세야 하고, 블록이 파일 중간에서 시작하면 시작 행 오프셋까지 더해야 한다.

## 2. 후보 변경 (한 가지만)

`apps/api/src/workspace.ts` 의 모델 입력 문자열에서 블록의 **각 줄 앞에 실제 파일 행 번호**를 붙인다(`40| 출시일: …`). 1000자로 나뉜 긴 줄의 조각에는 그 줄의 번호를 붙인다. 참고자료 머리말에 "각 줄 앞의 숫자는 파일 행 번호이니 행을 댈 때 그 숫자를 쓰라"는 한 문장을 더한다.

바꾸지 않는 것: 구간 선택(어느 블록을 고르는가), 블록 크기, 저장되는 근거 원문(`excerpt`, `docs/39`), 다른 프롬프트 문장, 모델, 모드.
행 번호가 붙으면 입력이 조금 길어진다. 입력 예산으로 잘리는 구간이 생기면 그 영향도 결과에 포함된다.

## 4. 채택 규칙 — 결과를 보기 전에 고정

1. 행 과제 PASS 비율의 Wilson 95% 구간이 **겹치지 않고 후보가 높을 때만** 개선으로 본다(`stats.ts` `compare` 가 "개선").
2. 값 과제가 "악화"면 채택하지 않는다.
3. 기존 맥락 8과제(`context-evidence.ts`, 조정에 쓰인 회귀 방지용)를 후보 코드로 3회 돌려 **23/24 이상**이어야 한다. 이 결과는 개선 근거로 쓰지 않는다.
4. 1이 "구분 불가"면 채택하지 않고, 결과와 탐지 가능한 최소 차이를 기록한다. 과제를 바꿔 다시 재지 않는다.
5. 기준 실행과 후보 실행은 같은 기기·같은 모델 파일·같은 설정으로 한다. 속도는 비교하지 않는다(기기 부하가 높다).
