# 자료 기반 출시 요약 — 실제 대표 업무 흐름 검증

2026-09-12. 새 기능을 추가하는 단계가 아니라, 개선한 기억·자료 기능이 승인·검증·복구까지 이어지는지 확인하는 한 가지 업무 표본이다. 하네스는 `apps/verify/src/eval/representative-workflow.ts`, 결정적 안전 시험은 같은 eval의 `__tests__/representative-workflow.test.ts`다.

## 업무와 안전 범위

서로 다른 제품코드·출시일·담당자를 가진 합성 출시 자료 3개를 사용한다. 가격은 모두 미정이다. 각 자료마다 이 실행이 새로 만든 UUID 제목의 대화에서 다음을 진행한다.

1. 한국어 답변 선호를 독립 메시지로 저장한다.
2. 출시 안내 자료를 API로 연결하고 실제 Postgres의 자료 사본을 확인한다.
3. 자료의 실제 값을 질문한다. 저장된 한국어 선호와 과거 본문이 전달됐는지, 모델에 전달된 출처 행이 답의 모든 사실을 포함하는지 확인한다.
4. 자료를 토대로 5줄 출시 요약 파일을 제안하게 한다. 파일 이름은 `representative-workflow-<run UUID>-<자료 id>.txt`이다.
5. 서버 실행 기록에서 정확한 새 파일 경로, 고정 허용 본문, 변경 전 파일 없음, 체크포인트/해시를 확인한 작업 1건만 승인한다. 다른 제안은 거절하며 허용 범위를 넓혀 통과시키지 않는다.
6. 하네스가 미리 지정한 읽기 전용 검증 명령만 별도로 승인한다. 실제 샌드박스 종료 코드 0과 검증 출력, 실행 기록의 `verified`를 모두 요구한다.
7. 호스트 파일을 실제로 읽어 고정 사실·형식·저장 해시를 확인한다.
8. 같은 변경을 API로 복구한다. 새 파일의 부재와 실제 DB의 action/run `restored` 기록을 확인한다.
9. 생성한 세션 ID, 조직, 정확한 UUID 제목, 파일 부재와 진행 중 작업 없음을 다시 확인한 후 이 세션만 휴지통으로 옮긴다. 자료·대화·실행 기록은 복구 가능한 상태로 남는다.

허용하는 파일 본문은 다음 형식이며 마지막 LF 한 개만 선택적으로 허용한다. 모델이 값을 자료에서 찾아야 하므로 질문/초안 요청에 정답을 넣지 않는다.

```text
출시 요약
제품코드: 자료의 실제 값
출시일: 자료의 실제 값
담당: 자료의 실제 이름
가격: 미정
```

검증 명령은 Node의 읽기/단언 코드로 고정되어 있다. 모델이 제시한 별도 명령은 승인하지 않으며, 읽기 도구를 포함해 추가 도구가 기록된 실행도 전체 흐름 통과로 인정하지 않는다. 사용자 원본 파일을 미리 만들거나 덮어쓰지 않는다. 실패로 파일/작업 상태가 불확실하면 임의 삭제·복구·세션 숨김을 하지 않고 비정상 종료와 보존 결과를 보고한다.

## 외부/유료 서비스 차단

명시적인 `AIOS_REPRESENTATIVE_WORKFLOW_TEST=1`이 없으면 실행하지 않는다. 기존 맥락 시험의 URL guard로 API/DB/Redis의 loopback 주소와 쿼리/fragment 우회 금지를 확인하고, API는 `http://127.0.0.1:8791`만 허용한다. HTTP redirect도 금지한다.

시험 프로세스에 외부 프로바이더 키가 없어야 하며 서버의 모델 목록도 모두 `local`이어야 한다. 각 응답의 실제 `routed` 이벤트가 local `qwen3:8b`인지 다시 확인한다. URL·환경·외부 오류 본문을 보고서에 출력하지 않는다. DB 연결은 소유권·저장 결과 읽기에만 쓰며 모든 대화/자료/승인/복구/휴지통 변경은 실제 API를 통한다.

## 결정적 검증

8개 단위 시험이 다음의 유효 사례와 결함을 함께 검사한다.

- 고정 자료 3개의 서로 다른 값과 미정 가격.
- run UUID/자료 ID를 통한 경로·셸 주입 거부.
- 정확한 새 파일/본문/해시 및 선택적 마지막 LF 승인, 중복 쓰기 거부.
- 다른 경로·추측 가격·기존 파일·손상 해시·추가 인자 거부.
- 쓰기 승인 전 검증, 다른 명령/cwd/purpose 거부.
- 다른 자료·빈 출처·부분 사실만 포함한 행·역전/범위 초과 행 거부.
- 실제 과거 본문/언어 선호가 전달되지 않은 상태 거부.
- 다른 ID·조직·이름 변경·이미 삭제된 세션 정리 거부.

## 실제 실행 기록

### 개선 전 후보 — 실패 이력 보존

첫 실행에서 자료 연결·저장된 선호·출처 행은 정상 확인됐지만, 모델은 세 자료 모두 실제 값 대신 `제품코드|출시일|담당|가격`이라는 열 제목을 답했다. **0/3 실패**이며 파일 작성 단계에는 도달하지 않았다. 이를 전체 업무 성공으로 세지 않는다.

이후 질문을 “열 제목이나 항목 이름 없이 실제 값”이라고 명확히 했다. 값 자체나 기대 정답을 프롬프트에 추가하지 않았고, 본문/출처/승인 검증 조건도 완화하지 않았다. 첫 실패 보고는 그대로 보존한다. 첫 실행의 새 세션 3개는 정확한 소유권·실행 기록 0건·시험 파일 부재를 확인한 뒤 휴지통으로 옮겼고, 별도 정리 기록을 남겼다.

개선 전 후보의 고정 질문 실행: **2/3 전체 흐름 통과, 1/3 실패, 자동 재시도 0회**. 질문의 실제 값과 출처 행은 세 자료 모두 통과했지만, `leaf`는 이전 질문의 `값|값` 형식을 파일에 그대로 사용해 새 5줄 요약 요구를 지키지 않았다. 본문 허용값 검사가 이 제안을 실제 거절했고 파일은 저장되지 않았다. 요구 조건을 완화하거나 성공할 때까지 재실행하지 않았다.

| --- | --- | --- | --- | --- |
| SKY-2610 / 2026-10-15 / 김하늘 | 통과 | 통과; 실제 검증 exit 0, 파일 부재와 DB `restored` 확인 | 만든 세션만 휴지통 | 24.917초 |
| LEAF-2611 / 2026-11-06 / 이서준 | 통과 | 실패; 잘못된 1줄 본문 제안을 거절, 파일 쓰기 0건 | 만든 세션만 휴지통 | 22.800초 |
| WAVE-2612 / 2026-12-09 / 박지우 | 통과 | 통과; 실제 검증 exit 0, 파일 부재와 DB `restored` 확인 | 만든 세션만 휴지통 | 26.757초 |

`leaf`의 거절된 본문은 `LEAF-2611|2026-11-06|이서준|미정`과 마지막 LF였다. 출처 사실은 맞지만 요청한 산출물 형식은 틀렸으므로 전체 업무 성공으로 계산하지 않는다. 이 후보에서 모델이 이전 턴의 형식을 다음 작업에 잘못 이어가는 한계를 확인했다.

개선 전 후보의 run UUID는 `2379de40-9371-4dc7-b10e-2706fa889ac0`, 실행 소스 SHA-256은 `ab017ea7efb6436cf96cd51be2227475d2c6c3ef6567062968d036d612818f90`이다. 보고서에는 실제 값 응답, 출처 행, 승인/action ID, 종료 코드, 읽은 파일 본문·해시, 복구 단계와 휴지통 결과를 함께 남겼다.

로컬 근거 폴더 `/Volumes/T7/bigdata/eval-baselines/representative-workflow/`:

- `2026-09-12T10-34-02.741Z-e7c2731b-7eb4-4625-8a9e-c031dc9d1498.json`: 첫 질문 표현의 0/3 실패. 원본 보존.
- `e7c2731b-7eb4-4625-8a9e-c031dc9d1498-cleanup.json`: 첫 실행의 생성 세션 3개에 대한 별도 소유 확인·휴지통 정리 결과. 원래 보고서의 정리 미완료 상태를 나중에 완료한 기록이다.
- `2026-09-12T10-36-44.799Z-2379de40-9371-4dc7-b10e-2706fa889ac0.json`: 명확화한 고정 질문의 2/3 통과, 1/3 거절 실패와 생성 세션 3개 정리.

첫 두 실행은 질문 표현이 다르므로 단일 정답률로 합치지 않는다. 기존 사용자 세션/자료/파일은 변경하지 않았고 시험 대화와 기록은 휴지통에서 복구할 수 있다. 지정한 시험 파일은 남기지 않았다. 타입·해당 파일 ESLint·결정적 단위 8/8 검사를 통과했다. 모델 전체 흐름 결과는 단위 검사 결과와 별개로 **실패를 포함한다**.

### 범용 요청 범위 개선 후 — 동일 고정 시험

생산용 시스템 프롬프트에 현재 요청의 산출물 조건을 우선하고, 이전 턴의 일회성 형식을 다음 작업에 이월하지 않는 공통 규칙을 추가했다. 명시적인 지속 선호만 기본값으로 사용하며 대화 답변의 형식과 파일 내용의 형식을 구분한다. 파일을 제안하기 전에 현재 요청의 구조·필드·형식을 대조하도록 했다. 특정 자료의 정답을 삽입하거나 모델이 낸 파일 본문을 하네스에서 고쳐 주는 방식은 사용하지 않았다.

통합 담당자가 새 생산 코드를 빌드·재시작한 뒤 실제 API에서 실행했다. 전달받은 기동 기록은 시작 시각 `2026-09-12T10:52:09.581Z`, instance `2912bba6-bfd6-4718-84cd-1fdd7ad54e93`이다. 대표 시험은 그 뒤 `10:53:02.127Z`에 시작했으며 종료 후 `/readyz`의 Postgres/Redis 정상도 읽기 요청으로 확인했다.

새 결과는 **3/3 전체 흐름 PASS, exit 0, 자동 재시도 0회**다. 세 자료 모두 9개 단계와 생성 세션의 휴지통 정리까지 완료했다. 고정 질문·5줄 본문 허용값·출처 검사·위험 승인·검증·복구 조건을 바꾸지 않았다. 실행 소스 SHA-256은 개선 전 2/3 후보와 동일한 `ab017ea7efb6436cf96cd51be2227475d2c6c3ef6567062968d036d612818f90`으로 실행 직후 다시 확인했다.

이 결과는 수정 전후의 같은 고정 업무 3건 비교이지 일반적인 모델 정확도나 무조건적인 형식 준수 보증은 아니다. 이번에는 성공했지만 이전에 실제 실패가 있었고, 비결정적인 모델의 더 넓은 업무·반복 표본이 필요하다는 한계는 남는다.

## 재현 명령

실제 사용자 서버가 켜져 있고 다른 모델 시험/위험 작업이 진행 중이지 않은 상태에서 `apps/verify` 디렉터리에서 실행한다. 이 명령은 합성 대화/자료/승인 기록을 생성하므로 정적 검사나 일반 CI에서 자동 실행하지 않는다.

```sh
AIOS_REPRESENTATIVE_WORKFLOW_TEST=1 \
AIOS_BASE_URL=http://127.0.0.1:8791 \
node --env-file=../../.env.local --import tsx src/eval/representative-workflow.ts
```

보고서는 기존 T7의 `/Volumes/T7/bigdata/eval-baselines/representative-workflow/`에 매 실행별 UUID 파일로 저장한다. 부분 진행도 저장하고, 모든 고정 자료와 정리가 확인되지 않으면 exit 1이다. 원본 환경 파일을 편집하거나 비밀 값을 출력하지 않는다.

## 이 근거로 주장하지 않는 것

- 고정 형식의 짧은 출시 안내 업무를 검사한 것이며 자유형 기획서·대형 프로젝트·임의 코드 수정의 일반 성공률이 아니다.
- 최초 0/3 실패가 보여주듯 질문 표현에 따라 로컬 모델이 요청을 잘못 이해할 수 있다. 통과한 실행만 합쳐 신뢰도 수치로 포장하지 않는다.
- 기존 데이터 복원, 다른 Mac 설치, 실제 외부 서비스, 다중 사용자 운영, 강제 전원 차단 무손실을 새로 검증한 결과가 아니다.
- 자료 출처의 실제 전달·파일 저장·지정 검증·복구 기록은 확인하지만, 원본 자료의 사실성이나 문서 전체의 정확성을 보증하지 않는다.
