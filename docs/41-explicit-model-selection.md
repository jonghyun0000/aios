# 41. 명시적 로컬 모델 선택 (NEXT_STEPS 5-3, HANDOFF 위험 37)

작성 2026-09-27. §1~§3은 구현 전에 적었다.

## 1. 재현 (키 없는 로컬 서버 8792, 실제 Postgres·Ollama, 설정 `LOCAL_LLM_MODELS=qwen3:8b`)

`POST /v1/sessions/:id/messages` 에 `routing.model` 을 지정했다.

| 지정 모델 | HTTP | 결과 | 저장된 메시지 |
|---|---|---|---|
| `qwen3:8b` (설정됨, `/v1/models` 가 사용 가능으로 광고) | 200 | SSE `error stream_failed: model 'qwen3:8b' unavailable` | `user` 만 |
| `exaone3.5:7.8b` (Ollama에 있으나 설정 안 됨) | 200 | 같은 오류 | `user` 만 |
| `없는-모델` | 200 | 같은 오류 | `user` 만 |

결함 세 가지:
1. **설정된 로컬 모델을 지정할 수 없다.** `AiRouter.rank()` 가 이 라우터의 카탈로그(로컬 모델 포함) 대신 코드 상수 카탈로그(`findModel`, 클라우드 모델만)를 조회한다. `/v1/models` 와 모순된다.
2. **잘못된 모델 지정이 HTTP 200으로 시작한다.** 검사가 스트림 시작(hijack) 뒤 라우터 안에서 일어나서 상태 코드로 거부할 수 없다.
3. **거부된 요청이 사용자 메시지를 남긴다.** 오케스트레이터가 모델 호출 전에 사용자 메시지를 저장하므로, 답 없는 질문이 대화 기록과 다음 요청의 맥락에 들어간다.

웹 UI는 `routing.model` 을 보내지 않는다. 영향 범위는 API·CLI(`--model`) 사용자다.

## 2. 완료 기준 — 구현 전 등록

1. `/v1/models` 에 있는 설정된 모델(`qwen3:8b`)을 지정하면 그 모델이 답한다(`routed` 이벤트의 모델 확인, 실제 Ollama).
2. 설정되지 않은 모델·없는 모델·어댑터가 없는 프로바이더의 모델은 **스트림 시작 전에 HTTP 400** `unknown_model` 이고, 메시지에 사용 가능한 모델 이름이 있다.
3. 2의 경우 **사용자 메시지를 저장하지 않는다**(대화 메시지 수 변화 0).
4. 명시 선택은 다른 모델로 조용히 대체하지 않는다(기존 규칙 유지).
5. 라우터 단위 시험: 설정된 로컬 모델 선택, 클라우드 상수 카탈로그에만 있는 모델의 거부, 사용자 지정 카탈로그 밖 모델의 거부. 채팅 라우트 시험: 400·미저장·모델 호출 0회.
6. 각 시험은 결함 주입으로 검출력 확인. 정적 4단계 통과.

## 3. 구현

- `packages/ai/src/router.ts` `resolveModel()`: 명시 모델을 이 라우터의 카탈로그(어댑터가 있는 모델만)에서 찾는다. 없으면 `unknown_model` 400, 사용 가능한 모델 이름(최대 20개) 포함, `retryable:false`. `rank()` 가 이것을 쓰며 명시 선택은 여전히 대체하지 않는다.
- `apps/api/src/routes/chat.ts`: 세션 확인 직후, 스트림 시작·메시지 저장 전에 `resolveModel()` 로 검사. `routing.model` 은 1~200자.

## 5. 남은 것

- 웹 UI에는 모델 선택 화면이 없다. 이번 수정은 API·CLI 경로다. Ollama에 설치돼 있어도 `LOCAL_LLM_MODELS` 에 없는 모델은 선택할 수 없다(의도한 동작, 메시지로 안내).
- CLI(`aios --model`)는 같은 API를 쓰지만 CLI 자체로 실행해 보지는 않았다.
- 모델별 능력·자원 요구에 따른 선택·대체 경로(사용자 우선순위 3)는 아직이다.
