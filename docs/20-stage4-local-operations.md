# 4단계 — 로컬 기동·진단·통합 백업·복원 검사

2026-09-12. 이 Mac + T7의 단일 로컬 실행판을 대상으로 한다. 클라우드 배포, 다른 컴퓨터 무설정 설치, 운영 데이터 자동 교체는 이번 범위가 아니다.

## 사용 경로

| 파일 | 역할 |
|---|---|
| `AIOS 시작.command` | DB·Redis·Ollama·모델·샌드박스 공유를 확인하고 화면/API/워커를 기동 |
| `AIOS 종료.command` | 이 시작기가 관리하는 앱만 정상 종료. 협업 저장과 워커 종료를 기다림 |
| `AIOS 상태 확인.command` | 현재 프로세스·포트·준비 상태, 유지보수 잠금, 로그 위치 확인 |
| `AIOS 백업.command` | 앱 정상 종료 후 DB·작업 파일·체크포인트 통합 백업 |
| `AIOS 복원 검사.command` | 최신 완료 백업을 새 DB·새 T7 폴더에 격리 복원하여 검사 |
| `AIOS 사용 패키지 만들기.command` | 소스·실행 스크립트·문서·잠금 파일을 재설치용 소스 패키지로 묶음 |

설정 화면의 **내 컴퓨터 운영**은 위 경로와 최근 백업/복원 검사 기록을 보여 주는 읽기 전용 화면이다.
`GET /v1/local/operations`는 `LOCAL_NO_AUTH` 환경의 `via=local`, owner 요청만 허용한다.
과거 검사 통과는 현재 파일 무결성이나 앱 정상 상태를 보장하지 않는다. 실시간 앱 상태는 상태 확인 파일로, 백업의 현재 무결성은 `node scripts/local-backup.mjs verify`로 확인한다.

## 기동과 종료

- 기본 URL은 `http://127.0.0.1:8791`. `AIOS_LOCAL_PORT`로 다른 비특권 포트를 사용할 수 있지만, 기본 웹 사용판의 작업 폴더는 기존 전용 폴더다.
- 포트 잠금으로 동시 시작을 막는다. 이미 정상 실행 중이면 기존 앱을 사용한다. PID뿐 아니라 생성 시각·명령·작업 폴더·리스닝 포트를 확인하며, 무관한 서버를 자동 종료하지 않는다.
- 소스·설정·pnpm 잠금/설치 의존성·빌드 산출물 내용이 같으면 API/Web 빌드를 재사용한다. 변경·산출물 손상·누락 시 다시 빌드한다. 비밀 환경 파일은 해시에 넣지 않는다. Vite 환경 파일/`VITE_` 환경값이 있으면 캐시를 사용하지 않는다.
- 상태는 `/Volumes/T7/bigdata/run/local-app/<프로젝트 해시>-<포트>/runtime.json`, 빌드 기록은 같은 폴더의 `build.json`이다. 값이 ready여도 실제 프로세스·준비 응답이 불일치하면 정상으로 표시하지 않는다.
- 종료 실패나 시간초과를 정상 종료로 포장하지 않는다. 강제로 죽이지 않으며 상태 확인과 로그 점검을 요구한다. 재시작은 사용자가 시작 파일을 다시 실행한다. 무한 자동 재시작·로그인 시 자동 시작은 설정하지 않았다.
- 협업 저장은 직렬화하여 오래된 스냅샷의 늦은 완료가 최신 편집을 덮어쓰지 않게 했다. 저장 실패는 재시도 가능 상태로 남고 최종 종료 실패로 전파한다. 워커 작업 종료 후 DB/Redis를 닫는다.
- DB·Redis·Ollama는 공유 서비스일 수 있으므로 앱 종료 시 그대로 둔다. T7를 분리하려면 다른 사용 작업까지 마친 뒤 해당 서비스를 별도로 종료해야 한다. Mac 자체 재부팅·강제 전원 차단 시험은 수행하지 않았다.

## 통합 백업의 일관성과 범위

`node scripts/local-backup.mjs backup`

앱이 켜져 있거나 포트 잠금, 실패한 종료 기록, 다른 원본 DB 연결이 있으면 백업하지 않는다. 유지보수 잠금을 먼저 잡으며 시작기는 포트 잠금 후 유지보수 잠금을 확인한다. 경합 시 시작 또는 백업을 중단한다.
Postgres의 public 테이블에 쓰기 방지 잠금을 잡고 같은 내보낸 스냅샷으로 custom-format dump와 테이블별 내용 해시를 만든다. 파일 복사 전·후 목록/내용, 시퀀스, DB 체크포인트 참조도 확인한다. 다른 프로그램에서 동시에 파일/DB를 수정하지 않아야 한다.

완료 백업: `/Volumes/T7/bigdata/backups/local/backup-<UTC시각>-<8자리 ID>/`

- `database.dump`: 전체 public 스키마를 포함한 PostgreSQL DB 덤프. 대화, 연결 자료, 프로젝트, 협업 바이너리, 기억/색인 벡터, 실행 기록 등.
- `workspace/`: `/Volumes/T7/bigdata/workspaces/my-first-project`의 일반 파일과 빈 디렉터리.
- `checkpoints/`: `/Volumes/T7/bigdata/checkpoints/stage3`.
- `manifest.json`: DB 테이블별 행 내용 해시/개수, 시퀀스 값, 파일 SHA-256/크기, 적용 범위, 제외 항목, 서명.

현재 기본 작업 폴더와 일치하는 실행 기록의 모든 checkpoint=true 항목은 실제 체크포인트 파일·이전/이후 해시·경로와 일치해야 한다. 다른 workspace_root의 DB 기록은 덤프에 보존되지만 그 외부 작업 폴더/체크포인트까지 복구한다고 주장하지 않는다. 해당 실행 수는 `otherWorkspaceRuns`로 명시한다(첫 시험 32건, 과거 QA 전용 작업 폴더).
신규 설치에서 체크포인트 참조가 0이면 체크포인트 폴더가 없어도 빈 스냅샷을 허용한다. 참조가 있는데 파일이 없으면 실패다.

제외: `.env.local`, 별도 API 키/서명 키, Ollama 모델, DuckDB/Parquet, Redis 캐시·대기 작업, macOS `._*` 파일. Redis 큐에만 남은 색인/기억 추출 작업은 복원되지 않으므로 다시 요청해야 한다. **DB와 작업 파일 자체에 담긴 민감한 내용은 포함된다.**
파일은 개별 512 MiB, 묶음 4 GiB, 항목 30,000개, DB 검증은 테이블당 100만 행까지 지원한다. 링크·장치·소켓·경로 탈출·정규화 중복은 거부한다. 한도를 초과하면 부분 성공으로 처리하지 않는다.

완료 전에 실패하면 `.partial`만 남고 최신 성공 기록을 갱신하지 않는다. 자동 보존기간 삭제·클라우드 업로드는 없다. 파일/복원본이 쌓이는 만큼 T7 및 PostgreSQL 볼륨 용량을 관리해야 한다.

## 서명과 안전한 복원 검사

`node scripts/local-backup.mjs verify [백업ID]`

`node scripts/local-backup.mjs restore-check [백업ID]`

ID 생략 시 이름순 최신 완료 백업을 선택한다. 임의 경로나 외부 덤프를 받지 않는다.
manifest 전체는 `/Volumes/T7/bigdata/secrets/local-backup-signing.key`의 32바이트 키로 HMAC-SHA256 서명한다. 파일과 해시 목록을 함께 바꿔도 서명이 불일치하면 DB에 실행하기 전에 거부한다. 키는 최초 백업 때 생성하며 자동 교체하지 않는다. **기존 백업을 사용하려면 이 키도 별도로 안전하게 보존해야 한다.**

exFAT의 chmod는 기밀성 보장이 아니다. 서명 키와 백업을 모두 바꿀 수 있는 로컬 사용자를 막는 보안 경계도 아니다. 신뢰할 수 없는 PostgreSQL dump는 SQL 코드를 실행할 수 있으므로 이 설치가 만든 신뢰된 백업만 사용한다.

복원은 `aios_restore_<시각>_<ID>`라는 존재하지 않는 새 DB와 `/Volumes/T7/bigdata/workspaces/.recovery/<DB명>`의 새 폴더에만 수행한다. 기존 DB/폴더를 삭제하거나 덮어쓰는 `--force` 옵션은 없다. 검증한 서명 목록에 맞춰 복사한 덤프를 사용한다.

검사 내용:

1. 서명, 필수 구성, 모든 파일의 SHA-256/크기/목록.
2. 실제 pg_restore 완료 후 29개 테이블의 행 내용/개수와 시퀀스 비교.
3. 복원된 DB와 체크포인트 파일의 참조/해시 정합성.
4. 모든 협업 문서에 실제 `Y.applyUpdate` 적용·재인코딩, 두 벡터 테이블의 실제 pgvector 자기 유사도 쿼리. 벡터가 없으면 not_present로 구분.
5. 복원 폴더 아래 독점 신규 표본에서 실제 앱의 체크포인트 복구 함수를 사용해 기존 파일 복구·신규 파일 제거·수동 변경 충돌 보존 시험.
6. 검사 전·후 원본 DB와 복원 DB 내용 불변, 백업 무결성 재확인.

성공 결과는 복원 폴더의 `restore-report.json`과 `/Volumes/T7/bigdata/operations/backup-status.json`에 남는다. 실패한 복원 DB/폴더도 자동 삭제하지 않는다. 시험이 만든 일시적인 체크포인트 표본만 정리한다.
**이것은 격리 복원 검사이며 운영본 전환이 아니다.** 복원 DB의 절대 작업 경로 메타데이터를 유지하고 API·워커를 자동 기동하지 않는다. 실제 운영 복구/다른 Mac 이관은 원래 경로·설정·키·모델을 준비하고 기존 데이터 교체 범위를 사용자가 정한 후 진행해야 한다. 원본 Redis 큐를 복원 워커에 물리지 않는다.

DB 도구 오류/시간초과로 작업 종료가 불확실하면 `maintenance.lock`을 남겨 새 시작·백업을 막는다. 무작정 잠금을 지우거나 DB를 지우지 말 것. `owner.json`의 작업과 로그, `pg_stat_activity`의 `aios-backup-*` 연결이 실제 종료됐는지 확인한 뒤 해당 잠금만 수동 복구한다. 잠금 키/비밀번호를 로그에 출력하지 않는다.

## 검증 근거

첫 실제 백업: `backup-20260912T023947Z-33af6f4d` — 7,978,049 bytes, 19개 파일, 현재 작업 폴더 체크포인트 9개.
격리 DB: `aios_restore_20260912t024057z_d876e45e` — 테이블 29개, 협업 문서 78개, 기억 벡터 1,500개/코드 벡터 2,340개(각 1024차원, 표본 자기 거리 0), 실제 파일 복구 3경로 통과.

새 단위 시험은 저장 실패·동시 저장 역전·워커 drain/연결 정리 실패, 포트/프로세스 신원·중복 시작·캐시 변조, 손상 manifest/파일/체크포인트·경로 탈출·기존 복원 대상 덮어쓰기·잘못된 운영 상태를 실제로 주입한다.
LLM 모델·프롬프트·추론 정책은 이번 단계에서 바꾸지 않았다. 과거 단계의 모델 품질 결과를 이번 변경 전체의 재검증으로 주장하지 않는다.

실제 사용자 시작기 정상 기동, 중복 시작 시 같은 instance 유지, 정상 종료 후 재기동 및 빌드 재사용을 확인했다(재사용 검사 단일 관측 2,970ms; 기동 전체 시간/다른 Mac의 성능 보장 아님).
앱 실행 중 백업 및 다른 실제 PostgreSQL 연결이 있는 오프라인 백업을 고의로 시도하여 모두 거부됨을 확인했다.

실제 협업 종료 내구성 **15/15 PASS**: 마지막 편집→peer 수신 26ms, 종료 명령 28ms, 해당 API의 SIGTERM 수신 로그 871ms(2초 디바운스 전).
종료 직전 DB에 없던 마지막 편집을 정상 종료 후 실제 Yjs 스냅샷에서 확인했다. 종료 코드0, 원래 API/워커 PID 소멸, 8791 리스너 없음, 동일 instance의 stopped 기록을 확인했다.
재현 스크립트 `apps/verify/src/stage4-shutdown.ts`는 **현재 관리 앱을 실제 종료하는 검사**이므로 사용자 작업 중 실행하지 않는다. 신규 QA 문서만 만들며 기존 문서/공유 서비스를 변경하지 않는다.
보고서: `/Volumes/T7/bigdata/eval-baselines/stage4/shutdown-2026-09-12T02-48-53-766Z.json`.

전체 브라우저 회귀 **87 PASS / 0 FAIL / 3 SKIP**(90개, 데스크톱·모바일, 2.5분). 3개 SKIP은 모바일 전용 반응형 검사를 데스크톱 프로젝트에서 제외한 것이다. 신규 운영 화면 4개 모두 PASS.

## 재난 복구 한계

T7에 있는 원본과 같은 T7의 백업은 디스크 고장·분실에 대비한 독립 백업이 아니다. PostgreSQL 볼륨은 기존 Colima 저장 위치를 유지했다. 키·DB 덤프를 포함하는 암호화된 별도 디스크/외부 보관은 사용자의 저장 위치와 권한 결정이 필요하며 자동 수행하지 않았다.
이전 `backup.sh`/`restore.sh`는 별도 서버 운영용 구형 스크립트다. 로컬 통합 복원 검사에서는 사용하지 않으며, `--force`나 구형 삭제/retention 명령을 섞어 쓰지 않는다.
