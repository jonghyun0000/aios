## 2. 재현한 문제

2026-09-27, 키 없는 로컬 서버(8792)에서 합성 자료로 재현했다.

1. 59행짜리 `제품계획.md`(40행에 `출시일: 2026-11-03`)를 대화에 연결하고 "출시일은 언제야?"라고 물었다.
2. SSE `workspace_context.sources`는 `[{id:"R1", fileName:"제품계획.md", startLine:1, endLine:59}]`였다. 파일 ID는 없다.
3. 답변은 날짜는 맞혔지만 **"39번째 줄에 따르면"이라고 틀린 행을 댔다.** 실제는 40행이다. 모델에는 행 번호 없이 원문 블록이 JSON 문자열로 전달되므로 모델이 행을 센다.
4. `GET /v1/sessions/:id/messages`의 assistant content에는 `text`·`toolCalls`만 있다. 근거는 어디에도 남지 않는다.

3번은 이 기능이 필요한 이유다. **출처가 붙어 있다는 사실은 답변이 정확하다는 뜻이 아니다.** 사용자가 원문을 직접 열어 대조할 수 있어야 한다.
모델에 행 번호를 함께 보내 인용 정확도를 높이는 일은 모델 품질 변경이므로 이 작업 범위에서 하지 않는다(§6).

## 3. 완료 기준 — 구현 전 등록

사용자 관점:

1. 참고자료를 쓴 답변 아래에 **전달된 구간 목록**(파일·행 범위)이 보이고, **새로고침·다른 대화 갔다 오기 후에도** 그대로 보인다.
2. 목록에 **한도·누락**이 표시된다: 연결 파일 수, 그중 구간이 전달된 파일, 전달되지 않은 파일 이름, 일부 구간만 전달됐는지, 단어 일치가 없어 앞부분 개요만 보냈는지.
3. 구간을 누르면 대화 상자에서 **모델에 실제로 전달된 원문을 행 번호와 함께** 보고, 연결 중인 파일이면 **앞뒤 문맥 행**도 본다.
4. 상태를 정확히 표시한다.
   - 파일이 연결돼 있고 전달 원문이 파일의 해당 행과 일치 → "파일 원문과 일치"
   - 답변 뒤에 파일 연결을 해제 → "연결 해제됨" 표시, 전달 원문만 보여 주고 파일 전체 문맥은 보여 주지 않는다
   - 답변 뒤에 같은 이름의 새 파일이 연결됨 → "이 답변은 이전 사본 기준" 경고
   - 파일 행과 전달 원문이 다름 → "불일치" 경고(성공으로 표시하지 않는다)
5. 대화 상자에 "전달된 구간은 답변의 정확성을 보장하지 않는다. 답변의 값·행 번호를 원문과 비교하라"는 안내가 있다.
6. 근거가 없는 기존 메시지와 계산 경로 답변은 지금과 같이 보인다.

경계:

7. 다른 조직의 대화·메시지·자료로는 열 수 없다(404). 휴지통의 대화도 404. 잘못된 ID는 DB 전에 400.
8. viewer 역할은 읽기만 하므로 열람 가능하다. 쓰기 권한 없이 새 데이터가 생기지 않는다(조회 전용 API).
9. 자료 안의 HTML·지시문은 텍스트로만 표시한다.
10. 열람 API가 실패하면 대화 상자에 오류를 보여 주고, 채팅 입력은 계속 쓸 수 있다.

저장·호환:

11. DB 마이그레이션 없이 기존 `messages.content` JSON에 `evidence`를 추가한다. 이전 메시지·이전 클라이언트와 호환된다.
12. 전달 원문은 답변당 최대 4구간 × 1000자 한도를 넘지 않는다(기존 선택 한도 그대로).

검증:

13. 단위 시험: 구간 선택이 파일 ID·정확한 전달 원문을 돌려준다(긴 줄 분할 포함), 열람 API의 조직·휴지통·ID·상태 판정, 화면 표시 변환.
14. 새 시험마다 결함 주입(해당 수정을 되돌리면 실패)을 확인한다.
15. 실제 Chromium + 실제 API·Postgres·로컬 모델로: 자료 연결 → 질문 → 근거 열기 → 새로고침 후 다시 열기 → 연결 해제 후 상태 → 같은 이름 새 파일 후 상태. 열람 API 실패 주입.
16. 실제 서버 두 개(키 없는 조직 / 개발 키 조직)로 조직 간 접근이 404인지 확인한다.
17. 정적 4단계와 기존 브라우저 회귀 전체를 다시 통과한다.

## 4. 설계

- 파일은 `workspace_files`에 불변으로 저장되고 수정 API가 없다(연결 해제는 `deleted_at`만 설정). 그래서 `fileId` + 행 범위로 원문을 다시 찾을 수 있다. 새 버전은 같은 이름의 **새 행**으로 들어온다.
- 모델에 보낸 블록 원문(`excerpt`)을 답변과 함께 저장한다. 파일 연결이 해제돼도 "무엇을 보냈는가"는 남는다. 크기 상한은 기존 선택 한도(4 × 1000자).
- 열람 API는 `GET /v1/sessions/:id/messages/:messageId/evidence/:sourceId`. 저장된 근거만 읽고 새 데이터를 만들지 않는다.

## 7. 확인하지 못한 것과 남은 문제

- (2026-09-27 갱신) 행 번호 오류는 NEXT_STEPS 5-2에서 따로 줄였다(`docs/40`: 홀드아웃 18% → 96%). 아래는 5-1 시점의 기록이다.
- **답변 본문의 행 번호 오류는 그대로다.** 재현에서 모델은 40행을 39행이라고 했다. 이번 기능은 사용자가 원문과 대조해 그 오류를 **발견**하게 할 뿐 **줄이지** 않는다. 모델에 행 번호를 함께 보내는 개선은 NEXT_STEPS 5-2 — 조정에 쓰지 않은 과제로 반복 평가한 뒤에만 채택한다.
- 답변이 어떤 구간을 실제로 **사용**했는지는 알 수 없다. "전달됨"만 표시한다. 전달되지 않은 사실을 모델이 지어냈는지도 이 기능으로는 판정하지 않는다.
- 참고자료 연결 전에 생긴 답변, 그리고 이 변경 이전에 저장된 답변에는 근거가 없다(소급 불가).
- 참고자료는 여전히 텍스트 64KB·대화/프로젝트 각 8개다(PDF·Word 미지원, HANDOFF 위험 21).
- 실제 스크린리더 청취, Safari/WebKit, 다른 Mac, 신규 사용자 관찰은 하지 않았다.
- 다른 조직의 대화 ID로 `GET /v1/sessions/:id/messages` 는 기존대로 200 + 빈 목록이다(유출은 아님, 이번 변경과 무관).
