## 100점의 수용 조건 — 배점을 바꾸지 않는다

1. **핵심 기능 20점:** 선언한 대표 작업을 처음부터 끝까지 수행하고 실패를 복구할 수 있다. 고정 회귀 과제와 실제 사용 사례에 추적 가능한 결과가 있으며, 장문·자료 누락·모델 한계가 사용자에게 드러난다. 모든 질문에 정답을 보장한다는 뜻은 아니다.
2. **신뢰성·안전 25점:** 알려진 높은 위험도의 인가·파일 경계 결함이 남지 않고, viewer/member/다른 조직 및 실패 경로를 회귀 시험한다. 승인·종료·복구 계약이 실제 저장소에서 검증되며, 중요한 데이터에는 원본 디스크 상실까지 포함한 승인된 독립 백업·복구 증거가 있다. 단일 프로세스 전제 등 미지원 범위가 강제되거나 분명히 표시된다.
3. **UX·접근성 15점:** 대표 사용자 흐름이 키보드, 좁은 화면, 오류·빈 상태에서 완결된다. 접근성 자동 검사뿐 아니라 초점 이동·읽기 순서·입력·승인·복구의 수동 검증과 개발자 외 신규 사용자의 첫 사용 관찰이 있다.
4. **재현 설치·운영 15점:** 지원하는 깨끗한 다른 Mac에서 문서만으로 준비·시작·실제 대화/도구·종료·격리 복원까지 수행한 기록이 있다. 필요한 의존성·모델·경로·용량·키를 실행 전에 진단하고, 실패가 기존 데이터나 설정을 덮어쓰지 않는다. T7 지원만 선언해도 되지만 개발자 개인 설정에 의존해서는 안 된다.
5. **검증·유지보수 15점:** 이식 가능한 CI가 실제 테스트를 선택하고, 중요한 DB·파일·협업·실행 통합 계약에는 반복 가능한 별도 검증이 있다. 결함 주입이 실패를 검출하고, 모델 품질과 결정적 코드 시험을 구분하며, 해당 릴리스에 대한 최신 근거와 남은 공백이 추적된다.
6. **공개 소개·배포 10점:** 첫 방문자가 제품 범위와 설치 요건을 이해하고 공개 체험에 접근한다. 체험이 모의 응답·가상 파일이면 명시하고 로컬 데이터/API에 연결하지 않는다. 실제 배포의 주요 화면·새로고침·잘못된 경로·접근성·링크를 검사하고, 코드 실행·기여·보안 제보의 진입점 및 재사용 권한 상태를 혼동 없이 안내한다.

여기서 100점은 **명시한 범위와 평가일의 수용 조건을 충족했다는 평가**이지 무결점·미래의 보안 보장·모든 환경 지원을 뜻하지 않는다. 사용자의 계정·다른 장비·중요 데이터 이동 같은 새 권한이 필요한 항목은 승인 없이 실행하거나 점수를 채우지 않는다.

### 수정 및 실제 검증 — 2026-09-12

- 협업은 **member 이상만 접속**하며 viewer는 문서 참가 전에 4403, 무인증은 4401로 거부한다. 실제 인증 함수와 Fastify WebSocket을 사용하고 DB/룸만 대역으로 한 API-key·세션 시험 5개가 통과했다. 이는 viewer용 읽기 전용 협업을 구현한 것이 아니라 접속 자체를 제한한 안전 패치다.
- 새 Yjs 문서와 별개인 구형 `/v1/ws` 릴레이도 `collab.update`만 member 이상으로 제한했다. viewer의 자기 조직 이벤트/구형 협업 읽기는 유지하며 잘못된 JSON 프레임의 null/배열/비문자열 필드를 거부한다. 독립 검토자가 기존 코드에서 viewer 발행·null 프레임 2개 실패를 확인했고, 패치 후 역할·조직 경계 포함 7개 시험이 통과했다.
- 세션 생성·변경·자료 연결/해제와 메모리 저장/삭제는 member 이상을 요구한다. viewer 거부 6개, member 정상 쓰기 6개, viewer 읽기 유지 1개가 통과했다. 패치 전 동일 viewer 시험 6개는 실제 라우트가 200을 반환하여 실패했다.
- 채팅 전송도 도구 사용 여부와 무관하게 member 이상을 요구한다. 기존 코드는 도구를 끈 viewer가 실제 오케스트레이터를 거쳐 모델 대역 1회·메시지 저장 대역 2회에 도달했다. 합성 회귀 13개 중 viewer 기본 전송/API-key·세션 및 auto/fast/thorough 모드 5개가 기존 코드에서 실패했고, 진입부 역할 검사 적용 후 13개 모두 통과했다. member의 정상 모델/저장 흐름, 다른 조직 대화의 404, viewer의 조직 범위 안 읽기도 유지한다. 실제 사용자 DB·LLM은 사용하지 않았다.
- 색인은 API 접수와 워커 실행 양쪽에서 프로젝트 소유권, 전용 폴더의 로컬 조직 소유권, `LOCAL_WORKSPACE_ROOT`, 실제 경로를 확인한다. 설정 없는 배포에서는 409로 중단하며 외부 폴더·링크 경로는 403이다. 워커는 `.gitignore`와 각 본문 읽기 전에 경로/링크 검증을 반드시 전달한다. 인덱서의 독립 라이브러리 호출은 기존 호환성을 유지하므로 API/워커 우회 사용자의 별도 경계까지 보장하지 않는다.
- 색인 API/워커 FS·DB 대역 시험 11개, 인덱서 6개(기존 청커 3개 포함)가 통과했다. 경로 검사와 워커 callback을 잠시 제거한 결함 주입에서 6개 실패, 인덱서 읽기 전 검증을 제거하면 2개 실패를 확인한 뒤 안전 코드를 복원했다. 링크/하드링크 결함은 FS 대역으로 검증했으며 T7의 물리적 링크 시험이라고 주장하지 않는다.
- 실제 T7에 독점 생성한 일반 텍스트 fixture에서도 지정 폴더의 내용만 임베딩 대역으로 전달되고 인접 폴더는 거부됐다. 실제 사용자 DB/LLM/개인 파일은 사용하지 않았다. `AIOS_INDEX_FS_TEST=1`일 때만 실행되는 별도 시험 1개이며 기본 Linux CI에서는 명시적으로 건너뛴다. 합성 fixture만 정리했다.
- 서버 로그는 쿼리 전체를 버리고 인증/쿠키 헤더를 가리며, 외부 Error의 message/stack을 고정 문자열로 바꾸고 config/cause를 기록하지 않는다. API/worker 초기화 실패와 worker 작업 실패도 허용된 오류 종류·코드·상태만 남긴다. HTTP/오류 요약 4개와 실제 진입점에 합성 실패를 주입한 3개 시험이 통과했다. 기존 원문 로그를 잠시 복원하면 진입점 시험 3개가 모두 실패함을 확인한 뒤 안전 코드를 복원했다. 요청 ID·경로와 정형 오류 정보는 남지만 상세 원인에는 비밀 없는 별도 계측이 필요하다. 기존 로그 검토/삭제나 실제 키 폐기는 하지 않았다. **WebSocket URL 토큰 방식 자체, 외부 프록시 로그, 프로젝트의 모든 별도 도구/프로세스 출력에 대한 전면 감사는 해결 범위가 아니다.**

위 수정 후 API 시험은 18개 파일 **110 PASS**였다. 기존 T7 전용 `checkpoints.test.ts`와 `local-operations.test.ts`는 이 실행에서 제외했고 새 T7 색인 시험 1개는 명시적으로 실행했다. 인덱서 **6 PASS**, API/인덱서 타입·린트와 diff 공백 검사가 통과했다. 이 결과는 실제 DB/Docker/LLM 통합 전체를 새로 실행한 결과가 아니다.

### 최종 코드의 추가 회귀 근거

최종 API 패치 후 기존 사용자 시작기로 정상 종료·재기동했다. 실제 로컬 웹 회귀는 **87 PASS / 0 FAIL / 3 SKIP**, 재시도 0, 133.56초였다. SKIP은 모바일 전용 3개의 desktop 실행이며 실패를 생략한 것이 아니다. 대화 관리 시험은 고정 제목의 첫 항목 대신 시험이 만든 세션 ID만 선택하도록 고쳐 동명의 사용자 대화를 보호했다. 중복 제목 결함 주입으로 이전 선택자의 잘못된 대상을 확인했다.

실제 준비 상태는 API·worker·Postgres·Redis 정상, doctor 14항목 확인, 고아 esbuild 0이었다. 이 실행에서 기존 DB 초기화·사용자 자료 교체·실제 통합 백업/복원은 하지 않았다. 브라우저 승인/복원 표시 검사 일부는 합성 응답을 사용하므로 실제 파일 복원 통합 시험으로 계산하지 않는다.

`9a5d150`의 [GitHub CI](https://github.com/jonghyun0000/aios/actions/runs/34685116460)는 실제 Linux runner에서 의존성 설치·타입·린트·빌드·이식 가능한 단위·doctor/데모 정책·정적 데모 Chromium 검사까지 성공했다. 로컬 실서비스 검사와 원격 정적 데모 검사를 합쳐 클라우드 실제 AI 서비스 검증이라고 주장하지 않는다. 이 근거는 위 83점의 회귀 확인이며, 독립 장비/사용자의 검증 공백을 없애는 추가 점수로 계산하지 않았다.
