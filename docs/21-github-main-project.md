# AIOS — 공개 메인 프로젝트의 개발 기준

2026-09-12 사용자 요청: AIOS를 GitHub 공개 저장소로 올리고 앞으로 집중할 메인 프로젝트로 삼는다. 저장소 이름은 `aios`, 계정은 `jonghyun0000`이다. 기존 한글 코딩 프로젝트는 삭제·교체·보관 처리하지 않는다.

## 저장소에 올리는 것

소스, 의존성 잠금 파일, `.env.example`, 마이그레이션, 실행 스크립트, 검증 코드와 기술 문서를 포함한다.
실제 환경 설정 `.env`/`.env.local`, 키, 대화/사용자 DB, 작업 폴더, 체크포인트, 통합 백업·복원본, 모델·대형 통계 데이터, node_modules·빌드·테스트 출력·macOS `._*`는 포함하지 않는다.
공개 전 파일 목록과 크기, 비밀 형태 및 실제 로컬 키와의 일치 여부를 점검한다. 자동 검색은 모든 비밀을 찾아낸다는 보장이 아니므로 이후 push에도 같은 검토가 필요하다.

로컬 개인 홈 경로는 동적인 홈 경로 또는 일반화한 예제로 정리한다. T7 경로는 현재 실행판의 제약을 설명하는 데 필요하므로 남긴다.
코드를 복제해도 모델·데이터·환경 설정이 자동으로 설치되지 않는다. 다른 운영체제나 T7가 없는 환경으로의 이식은 후속 개발 범위다.

## 검증·배포 경계

활성 GitHub Actions는 Node 22와 잠금된 pnpm 버전으로 의존성 설치, 타입·린트·빌드, 머신 독립 단위 검사를 수행한다.
T7/macOS 전용 테스트는 Linux CI 통과에 섞지 않는다. 기존 실제 로컬 브라우저/LLM/종료·복원 시험의 근거는 `docs/17`~`docs/20`에 별도로 남긴다.

기존 CI에는 main push 시 GHCR 이미지 업로드, staging/prod 배포, 실제 모델 호출 경로가 있었다. GitHub 업로드 요청은 이런 별도 배포까지 승인한 것이 아니므로 활성 워크플로에서 제외하고 `docs/examples/legacy-ci-deploy.yml`에 참고 예제로 보존한다.
원격 CI는 실행 전에는 통과했다고 주장하지 않는다. API 키·클라우드 계정·배포 환경·자동 릴리스는 별도 설정과 결정이 필요하다.

## 앞으로의 개발 방향

1. 실제 사용 피드백: 대화·자료·승인·검증·복구 흐름의 실패와 불편을 작은 이슈로 기록한다.
2. 설치 이식성: T7 고정 경로와 로컬 의존성 준비를 분리한다. 공개 데모 또는 범용 설치를 이미 제공한다고 홍보하지 않는다.
3. 품질 근거: AI 응답 품질은 반복 평가, 코드 기능은 결함 주입과 회귀 테스트로 구분한다. 모델의 완료 문구를 성공 증거로 삼지 않는다.
4. 운영 경계: 중요 데이터의 독립된 암호화 백업 및 실제 운영 복구 전환은 사용자가 범위를 정한 후 수행한다.

GitHub는 소스 버전 관리 장소이며 사용자 데이터 백업을 대체하지 않는다. Git 이력 이전의 개발 과정은 HANDOFF/검증 문서에 있고, 최초 업로드 이후부터 커밋으로 변경을 추적한다.

## 업로드 전 확인

공개 후보334파일을 감사했다. 실제 로컬 런타임 키와 일치하는 값, 개인 홈 계정명 경로, 50MB 이상 파일은0건이었다. 인증 실패 검증을 위한 의도적 더미 키2건은 실제 키와 구분했다.
`.env*`·`._*`·실행 로그 등을 거부하는 Git ignore 규칙을 확인하고, 명시적으로 선정한 소스 목록만 최초커밋에 포함한다. exFAT의 일괄 실행 권한은 Git index에서 일반파일/실행스크립트로 구분한다(원본파일 권한 변경 없음).

Node22.18.0·pnpm9.12.0으로 비밀 설정/node_modules/dist 없는 T7 새 복사본을 만들어 frozen-lockfile 설치, 타입·린트·빌드, 선별 단위293개를 실제 실행해 통과했다.
CI의 패키지 선택이0개일 때 실패하는 결함 주입도 확인했다. 이 결과는 Mac의 clean install 검증이며, 원격 Linux CI 상태는 [GitHub Actions](https://github.com/jonghyun0000/aios/actions)에서 별도로 확인한다.
