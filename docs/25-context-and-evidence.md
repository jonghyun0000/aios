## 재현한 문제와 수정 범위

웹 대화는 Redis 대신 DB의 최근 사용자·AI 메시지 100개를 복원한다. 빠른 경로에서는 장기 기억 검색도 생략하므로 100개 밖의 명시적 선호는 저장되어 있어도 모델 입력에서 사라졌다. 같은 이유로 오래된 한국어 요청을 영어로 수정한 사실을 놓쳤다.

자료 검색은 질문의 단어를 그대로 비교했다. `출시일은?`이 자료의 `출시일:`과 일치하지 않아 뒤쪽에 있는 날짜를 놓쳤다. 파일명 일치 점수를 모든 블록에 더해 다른 파일의 실제 근거를 밀어내는 문제도 있었다. 별도로 프롬프트 예산에서 섹션 제목 비용을 빠뜨려, 63토큰의 허용 예산에 추정 85토큰이 들어가는 합성 반례를 확인했다.

이번 수정은 추가 모델 호출·임베딩·DB 마이그레이션 없이 이 경로를 보완한다.

## 사용자가 제어하는 방식

명확한 예:

- `이 대화에서는 답변을 한국어로 해줘.`
- `앞으로는 답변을 영어로 해줘.`
- `앞으로는 답변을 목록으로 해줘.`
- `앞으로는 답변을 간결하게 해줘.`
- `이 대화의 답변 선호를 초기화해줘.`

초기화는 지원하는 답변 기본값을 비운다. 기존 대화·자료를 삭제하지 않는다. UI의 초기화 버튼은 초안을 자동 전송하지 않고 위의 명시 문장을 입력하도록 돕는다.

‘이전 대화 기억’ 끄기는 다음 요청에서 이전 본문·선호의 조회와 주입을 막는다. **채팅 저장을 끄는 기능은 아니다.** 다시 켜면 저장된 같은 대화에서 범위 내 맥락을 복원할 수 있다. 이 기능은 다른 대화/조직의 선호를 공유하지 않는다.

지원 문법 밖의 자연어는 조용히 사실로 승격하지 않는다. 사용자는 실제로 복원됐다고 표시된 항목을 확인해야 한다. 임의의 오래된 이름·약속·사실까지 모두 복원하는 기능은 이번 범위에 없다.

## API·화면 계약

기존 `workspace_context` SSE 이벤트를 확장했다. 실제 프롬프트 조립 뒤, 첫 답변 텍스트 전에 전송한다.

- `historyCount`: 모델에 실제 전달한 과거 본문 수. 상한 100.
- `files`: 연결되어 조회한 파일명 전체. 전체 파일을 읽었다는 뜻이 아니다.
- `sources`: 입력 예산을 통과한 `{ id, fileName, startLine, endLine }`만 포함한다. `R1` 같은 ID는 해당 응답의 자료 구간 표시다.
- `referenceMode`: `matched`는 단어 일치, `overview`는 일치 근거 없이 앞부분을 다양하게 뽑은 미리보기, `none`은 전달된 자료 없음.
- `excerpted`: 검색 또는 입력 예산 때문에 일부 구간이 제외됨.
- `memory`: `enabled`, `historyLimit:100`, `preferenceScanLimit:500`, 실제 `scannedUserMessages`, `restoredPreferences`.
- 선호 enum: `language=ko/en`, `format=bullets/plain`, `length=concise/detailed`.

자료는 JSON으로 인용한 **지시가 아닌 데이터**로 전달한다. 자료 기반 설명에는 제공된 출처를 사용하고 없는 사실을 만들지 않도록 요구한다. 사용자가 값만 요청하면 출처를 억지로 답변에 붙이지 않으며, 화면의 전달 자료 목록으로 범위를 확인한다. 출처 목록은 입력 전달의 증거이지 생성 답변이 그 자료와 항상 일치한다는 자동 판정은 아니다.

## 단위·회귀 근거와 남은 실제 통합 검증

신규 API 회귀의 최초 7개 중 4개가 원래 코드에서 실패했고, 구현 후 같은 검사를 통과했다. 인용·부정·조건문·자료 지시·다른 조직/세션·기억 끄기·500개 경계·초기화·실제 전달 출처까지 현재 35개를 검사한다. 프롬프트 예산 반례도 원래 코드에서 실패한 뒤 수정해 통과했다. AI 패키지 전체 126개, 관련 API 66개, AI/API/검증 앱 타입 검사와 담당 파일 정적 검사를 통과했다.

별도의 실제 DB↔API 검증은 다음 명세로 루트 담당자가 수행한다. 이 문서의 위 결과를 실제 DB 검증으로 바꾸어 부르지 않는다.

1. 이번 실행이 만든 새 세션만 API로 생성하고, 같은 고정 과제의 합성 과거 메시지를 그 세션/조직 조건으로 넣는다. 생성 시각은 행마다 증가시켜 최신 수정 순서가 명확해야 한다.
2. 합성 자료를 파일 연결 API로 올리고, 이번 세션의 Redis 캐시만 제거해 DB 복원 경로를 강제한다.
3. 같은 8개 과제 × 3회로 실제 답변·DB 저장·기억 이벤트·파일/행 출처를 검사한다. 오래된 수정, 초기화, 기억 끄기, 없는 사실, 자료 지시 거부를 포함한다.
4. 완료/실패와 관계없이 이번 실행이 만든 세션 ID만 휴지통으로 옮긴다. 기존 사용자 대화·자료·파일에는 쓰지 않는다.

## 현재 요청 범위 정책 보완과 고정 과제 재평가

2026-09-12 19:50 KST 후보. [대표 실제 업무 평가](29-representative-workflow.md)에서 이전 질문의 한 줄 답변 형식이 다음 파일 작성 요청에 이월돼, 정확한 파일 미리보기 승인 조건에 의해 거절된 사례를 확인했다. 일상 채팅과 도구 사용은 다른 시스템 템플릿을 쓰는데, 두 템플릿에 과거 일회성 형식의 적용 범위를 구분하는 공통 규칙이 없었다. 이는 관찰된 실패에 대한 원인 가설이며, 문구 존재만으로 모델 준수를 보장하지 않는다.

[prompt.ts](../packages/ai/src/prompt.ts)에 다음 범용 정책만 추가했다. 특정 평가 자료·정답·파일명은 넣지 않았다.
