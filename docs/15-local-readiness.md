# 로컬 사용 준비 검증 — 2026-09-11

이후 Enter 전송·사이드바 통합·빠른/깊이 생각 모드 변경과 최신 검증은 `16-chat-upgrade-v2.md`를 참고한다.

## 검증 범위

사용자 요청: 다음에 직접 실행하여 사용할 수 있는 수준으로 준비.
범위는 현재 Mac + T7의 로컬 실행판이며 클라우드 상용 배포 전체의 완료 선언이 아니다.
이전의 ‘핵심 작업 완료’는 단일 턴 평가 기준선 저장까지였다는 점을 정정한다.

## 바뀐 동작

- `AIOS 시작.command` 하나로 Docker/DB·모델 확인·마이그레이션·빌드·API·백그라운드 워커·브라우저를 준비한다.
- 사용자 포트는 8791. 개발 포트 8790과 충돌하지 않는다. 루프백에만 바인딩하며 로컬 화면은 키 없이 열린다.
- 로컬 인증에 Host·Origin·Sec-Fetch-Site 검사를 추가하여 외부 페이지 요청과 DNS rebinding Host를 거부한다.
- 시작기는 자식 프로세스를 소유한다. 종료 시 자신이 실행한 서비스만 정리하며, 이미 켜진 DB/Ollama는 유지한다.
- 로그와 작업 파일은 T7에 둔다. 정상 `dev-up.sh` 출력에서 API 키를 제거했다. `--export-only`는 셸 환경 주입용으로 유지한다.
- 로컬 UI는 구독이 없어도 정상 사용량을 표시하고 결제 화면에 로컬 안내를 표시한다.
- 채팅은 기본 질문 모드이며 사용자가 도구 허용을 켤 수 있다. 도구는 `/Volumes/T7/bigdata/workspaces/my-first-project`를 사용한다.
- 새 대화 생성 오류·HTTP 응답 오류·연속 단축키 전송을 처리하고 입력을 보존한다. 전송된 사용자 메시지와 생성 상태를 표시한다.
- 중단은 HTTP→오케스트레이터→모델·도구로 전달한다. 같은 대화의 중복 실행은 409로 거부한다. 취소된 요청이 모델의 장애율을 올리지 않는다.
- Docker 실행의 호스트 절대 cwd를 `/workspace`로 변환한다. 취소·타임아웃 시 해당 명령의 컨테이너도 정리한다.
- DuckDB는 별도 자식 프로세스에서 실행한다. 자식이 비정상 종료하면 진행 중 조회를 실패 처리하며, 다음 조회에서 새 자식을 시작한다. BigInt는 IPC에서 보존한다.

## 실제로 발견해 고친 사용 장애

1. Docker 실행에서 호스트 절대 cwd를 `/workspace/Volumes/...`로 잘못 해석했다. 같은 폴더를 가리키도록 변환하고 경계 밖 cwd는 거부한다.
2. Colima 기본 공유에는 T7가 없었다. 호스트에서 저장한 파일과 Docker가 읽는 디렉터리가 달랐다. 기존 홈 공유를 유지하면서 `/Volumes/T7/bigdata/workspaces`를 쓰기 공유에 추가했다.
   - 수정 파일: `$HOME/.colima/default/colima.yaml` (호스트 서비스 설정).
   - 변경 전 사본: `/Volumes/T7/bigdata/logs/local-app/colima-before-local-mount.yaml`.
   - VM/볼륨 삭제 없이 Colima를 정상 종료·재시작하여 적용했다.
   - 시작기는 호스트의 임시 표식 파일이 컨테이너에서도 보이는지 확인한다. 공유가 깨졌으면 사용 전에 오류를 표시한다.
3. 브라우저 검사 중 웹 번들을 재빌드하면 잠깐 파일이 없어지는 구간이 생겼다. 최종 브라우저 검사는 빌드를 완료한 서비스에서 실행했다.
4. 검증 실행기가 빌드 종료코드 2를 ‘프로바이더 계정 문제’로 분류했다. 프로바이더 전용 단계에서만 그 분류를 사용하도록 수정했다.

## 실행 증거

- 타입 검사·린트·단위 검사·빌드 통과. 이후 추가된 검증 스크립트와 테스트의 타입·린트·단위 검사도 통과했다.
- 브라우저: 58개 중 **55 PASS / 0 FAIL / 3 SKIP**. 제외된 3개는 데스크톱에서 실행하지 않는 모바일 전용 레이아웃 검사이며, 모바일에서는 모두 통과했다.
- 실제 화면에서 한국어 질문 전송·응답 표시·생성 중단을 확인했다.
- `scripts/verify-local-use.mjs`: 로컬 모델로 파일 생성→실제 Docker 실행→파일 내용 및 저장된 답변 검증을 두 과제에서 통과했다.
  - `aios-example-42.js`: 실제 출력 `42`, 대화 `b807db4d-dd7c-4967-8320-ec5cbfd84229`.
  - `aios-example-56.js`: 실제 출력 `56`, 대화 `abced3d9-2934-4f42-aaef-b4a3ace7ff3e`.
- `scripts/verify-local-recovery.mjs`: 실제 통계 자식 프로세스를 SIGKILL로 3회 종료했다. 매회 같은 API 프로세스가 살아 있고 다음 조회의 실제 데이터가 일치했다.
- `packages/tools/scripts/verify-cancel.ts`: 실제 sleep 컨테이너의 존재를 확인한 후 취소했다. 호출이 종료되고 컨테이너도 제거되었다.
- API 회귀 테스트는 실제 HTTP 연결을 열어 중복 요청 409·연결 해제 시 신호 전달·다시 전송 가능함을 검증한다.
- 브라우저 회귀 테스트는 저장 실패·모델 HTTP 실패·느린 세션 생성 결함을 주입한다. 오류 표시와 입력 보존·중복 방지를 확인한다.
- 통계 프로세스 단위 테스트는 실제 자식에 충돌을 주입하고 BigInt 결과를 그대로 재수신하는지 검사한다.
- Docker가 꺼진 상태에서 사용자 시작기로 기동하여 의존성 자동 기동과 파일 공유 검사를 통과했다.
- 최종 입력창 배치 수정 후 웹 빌드와 채팅 브라우저 회귀 6개를 추가 실행하여 통과했다.
- 시작기를 종료·재실행한 뒤 `56` 예제의 저장된 답변을 HTTP와 실제 화면에서 확인했다. 중복 시작 시 기존 화면을 재사용하는 분기도 확인했다.

## 사용상의 한계

작은 로컬 모델의 복잡한 작업 성공률을 위 두 예제만으로 보장할 수 없다. 모델이 생성한 코드는 사용자가 확인해야 한다.
원래의 exFAT 네이티브 충돌 원인을 해결한 것은 아니며, 장애 범위가 웹 서버 전체로 번지는 경로를 격리했다.
외부 프로젝트 선택 UI, 인터넷 패키지 설치, 외부 OAuth·Stripe 계정, 클라우드 프로바이더 실계정, 대규모 리포 부하는 이번 로컬 사용 검증 범위 밖이다.
