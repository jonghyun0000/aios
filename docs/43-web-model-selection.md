# 43. 웹 채팅의 명시적 모델 선택 (NEXT_STEPS 5-5)

작성 2026-09-27. 아래 완료 기준은 구현 전에 등록했다.

## 1. 재현과 원인

- 운영 API `GET /v1/models`는 200으로 설정된 `qwen3:8b`를 반환한다. `docs/41`에서 API·CLI의 `routing.model` 경로는 이미 검증했다.
- 현재 웹 채팅 화면에는 `응답 모드`(자동/빠름/깊이)만 있고 모델 선택 컨트롤은 없다. 화면에서 `qwen3:8b`를 지정할 수 없다.
- `apps/web/src/lib/stream.ts`의 전송 본문도 `routing.model`을 넣지 않는다. 따라서 화면만 추가해서는 명시 선택이 작동하지 않는다.
- 이 결함은 작업 전 HEAD `6ae9289`의 브라우저 화면과 소스에서 확인했다. 이번 변경으로 생긴 회귀가 아니다.

## 2. 완료 기준 (구현 전)

1. 채팅 화면에서 API의 `/v1/models`가 반환한 설정 모델만 고를 수 있다. `자동 선택`은 기본값이다. `open` 모델은 일시적 장애로 표시하고 선택할 수 없다.
2. 설정 모델을 고른 후 전송하면 요청의 `routing.model`이 그 모델 ID와 일치한다. 자동 선택은 `routing.model`을 생략한다. 응답 모드·기억·도구·이어서 하기 동작은 유지한다.
3. 모델 목록 조회가 실패해도 자동 전송은 가능하다. 오류를 보여주고 목록 재시도를 제공한다. 조회 중 또는 실패 시 검증되지 않은 모델 ID를 보내지 않는다.
4. 실제 설정 모델로 최소 1회 답변을 받고 SSE `routed` 모델과 저장된 `assistant` 답변을 확인한다. 실제 환경에 모델이 하나뿐이면 다른 모델의 속도·품질 비교는 주장하지 않는다.
5. 데스크톱·모바일 브라우저에서 목록·명시 선택·자동 복귀·오류와 재시도를 검사한다. 새 회귀 시험은 `routing.model` 전송을 제거한 결함 주입에서 실패해야 한다. 정적 4단계를 통과한다.

## 3. 범위 밖

- 모델 설치·다운로드, `LOCAL_LLM_MODELS` 설정 변경, 외부 API 키 사용, 공개 배포·푸시는 하지 않는다.
- 속도 향상은 이 기능의 완료 기준이 아니다. 모델별 성능은 별도 통제된 측정이 필요하다.

## 4. 구현

- `ChatPage`가 `/v1/models`의 설정 모델을 불러와 자동/명시 선택을 제공한다. 회로가 열린 모델은 장애 표시와 `disabled`로 선택 불가. 목록 실패는 메시지와 재시도를 노출하며 자동 전송은 그대로 가능하다. 목록 재조회 전에는 이전 선택을 비워 검증되지 않은 모델 ID를 보내지 않는다.
- `streamChat()`은 명시 선택일 때만 `routing.model`을 보낸다. 서버의 기존 모델 검증·400·메시지 미저장 정책(`docs/41`)은 변경하지 않았다.
- 키·로컬 모델 목록·데이터베이스 스키마·설정값은 건드리지 않았다.
