# 3단계 — 실행 결과 검증·위험 작업 승인·변경 복구

2026-09-12. 4단계 운영/패키징과 분리한 단일 로컬 API 안전 실행 기능이다.

## 구현한 범위와 이유

- API 도구 정책을 읽기 자동 / 쓰기 승인 / 명령 승인 / 네트워크 권한 거부로 고정했다. 예전 로컬 모드의 명령 자동 실행 예외를 제거했다.
- 공유 호스트 폴더를 다른 조직이 자신의 대화에서 열 수 없도록 `LOCAL_NO_AUTH_ORG_SLUG`의 조직에 작업 폴더를 결합한다. 실행 기록 DB의 조직 격리만으로 호스트 파일 격리가 되는 것은 아니므로 별도로 검사한다.
- 승인 대기는 5분이며, 정확한 서버 소유 인자에 결합된 1회용 작업 ID만 승인한다. 클라이언트는 boolean 결정만 보낼 수 있고 인자 교체를 거부한다. member 이상·동일 조직/대화만 허용한다.
- 거절·만료는 현재 도구 루프를 멈춘다. 연결 중단은 대기·실행에 취소를 전파한다. 새 서버 인스턴스에는 대기 승인 객체가 없어 재시작 전 승인이 실행되지 않는다. 미완 기록은 조회 시 interrupted로 표시한다.
- 명령은 네트워크 없음, 작업 폴더 읽기 전용 Docker로 실행한다. 쓰기 가능 셸을 승인만 받고 열어 주면 어떤 파일이 바뀔지 미리 알 수 없고 파일 도구의 백업을 우회할 수 있기 때문이다. `/tmp`는 임시 출력에 쓸 수 있다.
- 파일 쓰기는 64 KiB 이하 UTF-8 일반 파일로 제한한다. 작업 폴더 밖 / `.git`(대소문자 포함) / 링크 파일을 거부한다. 변경 전 전체 바이트·모드와 변경 후 내용·SHA-256을 폴더 밖 체크포인트에 먼저 저장하고 fsync한다. 백업 실패 시 실행하지 않는다.
- 승인 직전 상태의 해시를 승인 후 다시 검사한다. 쓰기는 완성된 임시 파일을 rename하여 중간 쓰기 실패가 기존 파일을 잘라 버리지 않게 한다. 실행 후 readback 해시를 확인한다.
- API의 쓰기·명령·복구는 하나의 작업 폴더 잠금으로 직렬화한다. 세션 잠금과도 연결하여 응답 중 복구·대화 삭제를 막는다.
- 새 migration `0005_execution_safety.sql`은 `execution_runs`와 `execution_actions`를 추가한다. 도구 인자·미리보기·출력(기본 최대 32 KiB)·실제 종료 코드·승인 시각·해시·복구 상태가 새로고침 이후에도 남는다. UI는 최근 20회 기록을 보여 준다.
- 지정 검증 명령은 모델이 고르는 명령이 아니라 사용자 입력으로 별도 실행되며, 이것도 승인 대상이다. 모든 도구 결과가 성공이고 지정 명령이 0으로 종료됐을 때만 지정 검증 통과로 표시한다. 파일 해시 일치는 동작 검증으로 승격하지 않는다.
- 모델의 중간 done을 전달하지 않고 검증·메시지 저장·실행 기록 갱신 후 단일 terminal done을 보낸다. 모델 종료 누락·검증 예외·출력 한도·반복 소진은 성공 종료가 아니다. 브라우저도 완료 이벤트 없는 SSE 종료를 오류로 표시한다.
- 복구는 현재 파일이 해당 변경의 after hash일 때만 가능하다. 수동/후속 변경은 409로 보존한다. 새 파일 복구는 해당 파일만 제거하고, 기존 파일은 직전 내용으로 되돌린다. 파일 내용 백업은 남으며 복구 후 이전 검증이 현재 상태를 보증하지 않음을 표시한다.
- 웹 안전 실행에서는 전체 저장소 `git add -A` 자동 커밋을 하지 않는다. 관계없는 사용자 변경과 훅 실행을 묶지 않기 위해서다. 라이브러리 직접 호출용 기존 Git 경로는 이번 UI 기능과 구분한다.

## API

- `POST /v1/sessions/:id/messages`: `tools.enabled: true`, 선택 `verificationCommand`. 도구 사용에는 서버 `LOCAL_WORKSPACE_ROOT`가 필요하며 클라이언트 호스트 경로로 바꿀 수 없다.
- `GET /v1/sessions/:id/executions`: 동일 조직의 살아 있는 대화 실행 기록.
- `POST /v1/sessions/:id/executions/:actionId/approval`: `{ "approve": true }` 또는 false. 그 외 키는 거부.
- `POST /v1/sessions/:id/executions/:actionId/restore`: `{ "confirm": true }`. 변경 충돌/실행 중은 409.
- SSE `execution_update`는 기록을 다시 조회할 신호다. 모델이 생성한 출력은 상태 판정이나 승인 요청으로 해석하지 않는다.

테스트는 실제 사용자 원본이 아닌 전용 QA 폴더와 새 대화만 사용한다.

실제 DB/Docker/API 하네스 최종 **14/14 PASS**: `/Volumes/T7/bigdata/eval-baselines/stage3/execution-2026-09-11T17-42-17.911Z.json`.
그중 로컬 qwen3:8b의 승인→쓰기→지정 검증→복구는 **3/3**이다. 앞선 실행은 12/12, 13/13이었고 잘못된 도구 인자 기록과 다른 조직의 호스트 폴더 접근 차단 검사를 추가했다.
실제 다른 조직 API 키로 자기 대화를 만든 뒤 도구 사용을 요청해 **HTTP 403**도 확인했다. 기록 조회만 차단되는 것으로 파일 격리를 증명했다고 하지 않는다.
최종 타입·린트·단위·빌드 **4 PASS**. 전체 브라우저 **83 PASS / 0 FAIL / 3 SKIP**(86개, 1.8분; SKIP은 데스크톱에 적용하지 않는 모바일 전용 3건).
조직 경계 최종 보완 후 사용자 시작기로 재기동하고 안전 실행 브라우저 **8/8 PASS**를 다시 확인했다. 전체 브라우저 86개를 이 마지막 API 변경 뒤 다시 돌렸다는 뜻은 아니다.
최종 서버 127.0.0.1:8791의 readyz에서 Redis/Postgres 정상, 고아 esbuild 없음. 소스·사용 안내·인수인계를 함께 갱신했다.

최종 모델 검증 일부는 브라우저 회귀와 함께 실행했으므로 소요 시간을 성능 기준선으로 사용하지 않는다.

정정: 기존 Phase4 하네스는 비정상 종료도 `ok=true`라고 기대했다. 이제 실제 종료 코드 42를 `ok=false`로 판정한다. 완료 게이트 검사 예외를 ‘완료’로 간주하던 이전 주석/판정도 검증 실패로 정정했다.
