# 2단계 — 일상 작업공간

2026-09-12. 사용자 요청 ‘다음단계진행’에 따라 1단계 다음 범위만 구현했다. 3단계 실행 승인/롤백과 4단계 패키징/백업은 아직 하지 않았다.

## 사용할 수 있는 것

- 사이드바 제목·본문 검색, 페이지 추가 조회, 이름 변경, 확인 후 휴지통 이동, 휴지통 목록과 복구.
- 자료·프로젝트 창: 프로젝트 생성/연결/연결 해제, 대화별 또는 프로젝트 공용 참고 파일, 파일 연결 해제.
- 웹 채팅은 Redis 캐시 대신 DB에 저장된 최근 사용자·AI 메시지 최대 100개를 맥락 원본으로 사용한다. 캐시 유실·오염이 이 원문을 덮어쓰지 않는다.
- Enter/Shift+Enter/한글 조합 보호, 자동/빠른/깊이 생각, 기존 깔끔한 사이드바 디자인과 로컬 시작기를 유지한다.

## 설계와 안전 경계

- `0004_daily_workspace.sql`은 추가 마이그레이션이다. 기존 메시지를 지우지 않으며 `sessions.deleted_at`만 변경한다. 휴지통은 실제 삭제가 아니다.
- 검색은 조직 범위에서 제목과 메시지 본문을 `strpos`로 조회한다. `%`, `_`도 문자 그대로이며 SQL 매개변수를 사용한다.
- 페이지 커서는 UTC 마이크로초 시각과 UUID를 함께 보존한다. JS Date의 밀리초 반올림으로 다음 페이지를 건너뛰지 않는다. 새 목록은 새 커서 형식이며 옛 시각 전용 커서를 사용하던 외부 클라이언트는 처음부터 다시 조회해야 한다.
- 전송/메타데이터 변경/파일 변경은 같은 단일 API 인스턴스의 세션 잠금을 공유한다. 파일 개수 제한은 DB 트랜잭션과 세션/프로젝트 행 잠금으로 지킨다. 여러 API 인스턴스를 동시에 운영하는 분산 잠금은 아직 아니다.
- 모든 대화·프로젝트·파일 조회/변경에 조직 조건을 적용한다. 다른 조직 프로젝트 ID를 새 대화에 붙이는 기존 경로도 막았다. 조직 내부 자료는 같은 조직 범위로 공유되며 개인별 비공개 분리는 추가하지 않았다.
- 파일 업로드는 호스트 경로 대신 브라우저가 읽은 작은 UTF-8 텍스트 사본이다. Postgres에 저장하고 사용자 파일은 수정/삭제하지 않는다. 로컬 앱의 외부 AI 키는 시작기에서 비워 둔다.
- 파일당 64KiB, 활성 파일은 대화/프로젝트 각각 8개. 숨김/경로 포함 이름, 일부 비밀 파일 이름, 바이너리/손상된 UTF-8, 지원 밖 확장자는 거절한다. 이것은 모든 비밀을 탐지하는 보안 스캐너가 아니다.
- 자료는 1,000자 안팎의 구간으로 나눠 질문 단어와 파일명 일치로 순위를 매기고 최대 4구간을 전달한다. 임베딩/추가 모델 호출을 하지 않는다. 참고자료는 지시가 아닌 DATA로 인용하고 도구 허용은 별도다. 이 표시는 모델의 인젝션 저항성을 보장하지 않는다.
- 기존 프롬프트 예산은 그대로다. 최근 100개를 불러와도 입력 한도 때문에 실제 전달분은 더 적을 수 있다. Redis 요약도 오염되거나 만료될 수 있어 DB 원문 경로에 합치지 않는다. 무제한 회상/장문 요약 복원은 구현하지 않았다.
- 프로젝트는 자료·대화 묶음이며 실제 디렉터리 연결이 아니다. 도구 접근 감옥(`/Volumes/T7/bigdata/workspaces/my-first-project`)을 넓히지 않았다.
- 읽기/저장 실패를 UI에 보여 주고, 이름 입력과 기존 파일 목록을 보존한다. 프로젝트 생성은 성공했지만 대화 연결이 실패하면 생성 사실을 알리고 기존 목록에서 다시 연결하게 한다.

### 정적·브라우저 검증

- 최종 타입·린트·단위·빌드 **4 PASS / 0 FAIL**. 최종 화면 회귀 결과는 HANDOFF §0에 함께 기록한다.
- 최종 사용자 시작기로 재기동한 뒤 전체 브라우저 실행: **75 PASS / 0 FAIL / 3 SKIP**, 78개(데스크톱·모바일, 1.7분). SKIP 3개는 데스크톱에 적용하지 않는 모바일 전용 조건이다. 자료 창 닫기 후 키보드 포커스 복구도 포함했다.
- 추가 브라우저 6개는 실제 검색→이름 변경→휴지통→복구→새로고침, 파일 사본 저장→프로젝트 공유→해제, 저장 HTTP 503 결함 주입을 포함한다.
- 단위 테스트는 파일 제한·관련 구간 선택·DB 순서 복원·소유권·세션 잠금·커서 정밀도와 모델에 전달된 실제 요청을 검사한다.
- 결함 주입: 캐시 삭제/오염, 모델 요청에서 복원 기록 제거, HTTP 503을 실제 경로에 주입하여 판별했다.
- 테스트 자체 보완: 처음 데스크톱 테스트가 모바일 전용 숨겨진 버튼을 기다려 실패했다. 표시 여부로 분기한 뒤 새 기능 6개 전부 통과했다. 모델 요청 객체의 뒤늦은 변경을 읽던 테스트는 호출 시점 스냅샷으로 바꿨다. 첫 실패를 제품 통과로 세지 않았다.
- 정정: 첫 API 보고서(`16-49-14.840Z`)의 조직별 메시지 격리 검사는 빈 대화를 대상으로 하여 검출력이 부족했다. 메시지가 실제 존재하는지 하한 단언 후 다른 조직으로 조회하도록 고쳐 전체 3회 반복 평가를 다시 실행했다. 위 최종 보고서만 채택한다.
- 최종 점검에서 창을 닫은 뒤 키보드 포커스를 복원하고, 생성 중 화면 이동을 취소 신호로 처리했다. 프로젝트 조회 조인에도 조직 조건을 넣어 예전의 잘못된 연결이 다른 조직의 RAG로 이어지지 않게 했다.
