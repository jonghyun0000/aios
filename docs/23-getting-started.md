# 처음 복제한 사람을 위한 시작 안내

AIOS에는 서로 다른 두 가지 사용 경로가 있습니다. **공개 체험 데모**는 샘플 데이터와 시뮬레이션으로 화면·작업 흐름을 살펴보는 앱입니다. **전체 로컬 앱**은 실제 DB·Ollama·작업 폴더를 사용하는 기존 Mac/T7 환경용 앱입니다.

현재 저장소는 전체 앱을 아무 Windows/Linux/Mac에나 자동 설치해 주는 제품이 아닙니다. GitHub에서 소스를 복제했다고 DB, 모델, 비밀 설정, 사용자 작업 파일까지 생기는 것은 아닙니다.

## 1. 먼저 화면만 체험하기

설치 없이 [AIOS 공개 체험판](https://aios-demo-mu.vercel.app)을 열 수 있습니다. [체험 범위·검증 기록](24-public-demo.md)을 함께 확인하세요.

이 경로는 Docker, Postgres, Redis, Ollama, 외부 AI 키, `.env.local`, T7가 필요하지 않습니다. 실제 AI 답변·파일 실행·백업이 일어나는 서비스는 아닙니다. 개인 정보나 비밀을 체험용 입력에 넣지 마세요.

로컬에서 데모를 실행하려면 Node 22 이상과 pnpm 9.12.0을 준비합니다. 원격 CI에서 사용하는 Node 기준은 22입니다.

```bash
git clone https://github.com/jonghyun0000/aios.git
cd aios
node scripts/doctor.mjs --demo
```

아직 의존성을 설치하지 않았다면 `루트 의존성`과 `데모 의존성`이 `준비 필요`인 것이 정상입니다. doctor가 대신 설치하지 않습니다. pnpm이 없거나 버전이 다르면 9.12.0을 직접 준비한 뒤 진행하세요.

```bash
pnpm --version
pnpm install --frozen-lockfile
node scripts/doctor.mjs --demo
pnpm demo
```

첫 설치에는 패키지 다운로드, 시간과 디스크 공간이 필요합니다. `pnpm demo`가 표시하는 로컬 주소를 브라우저에서 엽니다. 종료는 실행한 터미널에서 `Ctrl+C`입니다. 이 명령은 **데모만** 시작하며 기존 전체 앱의 8791 포트나 DB를 종료하지 않습니다.

정적 파일을 만들 때는 다음 명령을 사용합니다.

```bash
pnpm build:demo
```

산출물은 `apps/demo/dist`입니다. doctor의 성공은 이 빌드 명령의 성공이나 브라우저 동작을 대신하지 않습니다. 빌드/배포가 필요할 때는 별도로 실제 결과를 확인해야 합니다. 공개 배포의 검사 범위는 [체험판 배포 기록](24-public-demo.md)에 구분합니다.

## 2. 기존 Mac/T7에서 전체 앱 사용하기

이미 준비된 기존 로컬 환경을 사용하는 경로입니다. 다른 컴퓨터에 소스만 복제한 상태의 설치 절차와 혼동하지 마세요.

```bash
node scripts/doctor.mjs
```

다음을 읽기 전용으로 확인합니다.

- Node 버전, 저장소 구성, pnpm 설치 메타데이터, 루트 직접 의존성의 설치 메타데이터
- macOS 여부, `/Volumes/T7`, 기존 전용 작업 폴더와 모델 폴더의 존재
- `.env.local` 존재, 변수명, 빈 값/누락 여부. 기본 필수 변수는 `DATABASE_URL`, `LOCAL_LLM_BASE_URL`이며 외부 AI 키는 필수가 아닙니다.
- 로컬 소켓을 사용하는 Docker CLI/엔진 및 `1ai-postgres-1`, `1ai-redis-1`의 실행·healthcheck 상태
- 고정 loopback Ollama의 모델 목록과 설정된 대화·임베딩 모델의 존재. 추론이나 모델 다운로드는 실행하지 않습니다.

준비가 부족하면 해당 항목의 `다음:` 안내를 확인하세요. doctor는 Docker/Colima/Ollama를 켜지 않으며, 컨테이너·DB·모델·폴더·설정 파일을 만들지 않습니다. T7가 없다고 같은 이름의 빈 폴더를 만들어 해결한 것으로 취급해서는 안 됩니다.

현재 로컬 경로는 다음과 같이 고정되어 있습니다.

| 항목 | 현재 경로/범위 |
| --- | --- |
| 앱 작업 폴더 | `/Volumes/T7/bigdata/workspaces/my-first-project` |
| 모델 저장소 | `/Volumes/T7/bigdata/ollama-models` |
| 실제 시작기 | `AIOS 시작.command` |
| 실제 종료기 | `AIOS 종료.command` — DB/Redis/Ollama는 유지 |
| 실행 중 앱 상태 | `AIOS 상태 확인.command` |
| 웹 앱 | `http://127.0.0.1:8791` |

환경을 직접 준비할 때는 [처음 사용하기](../처음%20사용하기.md)와 [4단계 로컬 운영](20-stage4-local-operations.md)을 먼저 확인하세요. **기존 `.env.local`을 예제 파일로 덮어쓰지 마세요.** 모델/작업 파일/DB/키는 GitHub에 없으며, 데이터 경로와 Docker의 폴더 공유도 별도 준비가 필요합니다. 기존 T7 환경에서 설치 작업을 할 때도 캐시/모델/새 산출물의 저장 위치를 T7로 유지하세요.

전체 앱의 외부 공개는 이 시작 안내의 범위가 아닙니다. 로컬 인증 생략 모드를 인터넷에 노출하지 마세요. 온라인 실제 AI/파일 실행 서비스에는 별도 백엔드, 인증, 사용자별 격리, 자원 제한과 비용 결정이 필요합니다.

## 3. 진단 결과를 읽는 법

```bash
node scripts/doctor.mjs --help
node scripts/doctor.mjs --json
node scripts/doctor.mjs --demo --json
```

의존성이 설치되어 있으면 `pnpm run doctor`, `pnpm run doctor --demo`도 사용할 수 있습니다. `pnpm doctor`는 pnpm 자체의 다른 명령이므로 반드시 `run`을 넣습니다. 설치 전에는 Node로 직접 실행하는 명령이 패키지 매니저 자동 준비를 피하기 쉽습니다.

| 표시 / JSON 상태 | 의미 |
| --- | --- |
| 확인 / `ok` | 해당 항목에 적힌 범위만 실제 관측함 |
| 권고 / `warning` | 필수 조건과 별개의 권고(현재 항목은 보수적으로 확인/준비 필요/미확인으로 구분) |
| 준비 필요 / `blocked` | 필요한 전제가 없거나 기준에 맞지 않음 |
| 미확인 / `unknown` | 권한, 시간 초과, 잘못된 응답, 지원하지 않는 형태 등으로 결론을 내리지 못함 |

종료 코드는 `0`(검사한 준비물 확인), `1`(준비 필요 또는 미확인), `2`(잘못된 인자 또는 진단 내부 오류)입니다. JSON에는 `schemaVersion`, `mode`, `ready`, `exitCode`, `checks`, `limitations`가 있습니다. 누락/미확인 상태는 성공으로 계산하지 않습니다. 완료율이나 준비도 점수는 제공하지 않습니다.

pnpm은 검사 중 실행하지 않고 선택된 설치 패키지 또는 **이미 설치된** Corepack 캐시를 읽습니다. 알 수 없는 shim, 아직 다운로드되지 않은 Corepack 패키지, 9.12.0이 아닌 버전은 통과시키지 않습니다. 설치되어 있어도 `미확인`이면 PATH와 `pnpm --version`을 직접 확인하세요. 메타데이터 존재 확인은 실행 파일의 무결성이나 버전 명령의 실제 성공을 증명하지 않습니다.

외부 명령과 Ollama 응답에는 각각 약 2.5초 제한을 적용합니다. 진단이 만든 명령 프로세스만 시간 초과 시 종료하며, 기존 서비스는 건드리지 않습니다. 원격 Docker 컨텍스트는 조회하지 않습니다. `.env.local`은 셸로 실행하지 않으며 변수 확장/명령 치환 등 복잡한 구문은 `미확인`으로 남깁니다. 출력에는 설정 값, 키, 원본 명령 출력, 예외 메시지를 넣지 않습니다. 진단 결과를 공유할 때도 변수명과 사용 환경에 민감한 내용이 없는지 한 번 확인하세요.

전체 앱 진단이 모두 `확인`이어도 다음은 **별도 검증**입니다.

- 앱 프로세스의 현재 생존과 정상 응답 — `AIOS 상태 확인.command`
- DB 연결 인증·스키마·마이그레이션, 실제 대화와 임베딩
- Docker의 전용 작업 폴더 공유, 승인/실행/복구 동작
- 백업의 무결성, 실제 복원과 다른 컴퓨터 이관

기존 전체 앱용 로컬 시험을 새 컴퓨터나 사용자 데이터에 무심코 실행하지 마세요. 특히 과거 전체 검증의 phase8에는 삭제/롤백 단계가 있습니다. 공개 CI의 머신 독립 검사와 Mac/T7의 실서비스 검증은 서로 다른 범위입니다.

## 4. doctor 자체 검사

```bash
node --test scripts/doctor.test.mjs
```

파일시스템/서비스 응답을 주입하여 T7·Docker·설정 변수·의존성 누락, 잘못된 응답과 미확인 상태를 검출합니다. 실제 격리된 짧은 자식 프로세스/loopback HTTP 서버로 timeout도 확인합니다. 사용자 DB·T7 파일을 생성하거나 서비스에 변경을 가하지 않는 머신 독립 검사입니다.
